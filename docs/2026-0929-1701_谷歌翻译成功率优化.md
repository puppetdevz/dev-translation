## 1. 背景、目标与非目标

用户反馈 Google 翻译失败率高，示例为已安装 uTools 插件弹出「Google 翻译不可用，请切换至其他引擎」并附打包后 `assets/index-*.js` 的调用栈。该提示**不足以定位底层原因**：不能据此断言是 429、网络不可达、超时、依赖缺失，或响应格式变化；也未证明该安装包与本仓库当前源码完全相同。当前无脱敏的同次失败状态码/来源级日志及可量化基线。

**目标（已确认）**：在国内普通网络场景，优先提高 **Google 引擎自身**于现有引擎总时限内返回非空译文的比例，而非靠其他一级引擎兜底来充当 Google 成功；先使失败可安全归因，再优化免费免密直连的来源分时与切换，并提供用户**自填、默认关闭**的无认证 HTTP(S) CONNECT 代理作为可选路径。沿用既有一级故障转移，代理不可达且尚有预算时回退直连。

**非目标/条件边界（已确认）**：不接入 Google Cloud Translation 付费 API，不内置公共代理，不部署自建中转服务，不支持 SOCKS5 或代理用户名密码；不为 Google 增加超过现有 `engineResponseTimeoutSeconds` 的总时限（默认 5 秒，合法 1–60 秒）。如果该网络下所有 Google 来源都不可达，**不承诺未配置代理时一定能翻译成功**；应安全提示用户可自填可用代理或切换一级引擎。不改变 DeepL、DeepLX、AI、自定义 AI、词典的请求方式及一级统计语义。来源级重试不是无限试探，不以旋转公共 IP、绕过上游限流为目标。

## 2. 现状核对与调研结论

| 模块 | 核对结果及实施关联 |
| --- | --- |
| `public/preload/services.js` | Google 联网请求均在 CommonJS preload。`sourceLibrary`（约 363 行）延迟加载 `google-translate-api-x`，目前 `forceBatch: true`；`sourceGtxEndpoint`（约 402 行）请求 `translate.googleapis.com/translate_a/single?client=gtx&dj=1`；`sourceClients5`（约 428 行）请求 `clients5.google.com/translate_a/t`。`translateWithSources`（约 471 行）固定按 library → gtx → clients5 串行，首个成功返回；源异常会被吞掉并继续，最终仅保留最后一个 HTTP 状态或总错误。若首源挂住耗尽共享预算，后两源没有试探机会。`googleTranslate`（约 729 行）有 24h/200 项 LRU 与同 key inflight 共享/等待者取消；不能因改造破坏隔离及缓存正确性。 |
| `src/Translate/index.vue`、`utils/engineBridge.js` | 普通翻译经 `window.services.googleTranslate(text, from, to, timeoutMs)` 调用，`runEngineFailover` 为各已调用引擎独立截止并串行回退；524 仍立即回退。Google 最终才结算一次成功或失败；缺桥接是 `skipped`。只改 preload 内单次 HTTP 超时不能规避外层总预算。 |
| `src/Translate/components/SettingsPage.vue`、`utils/engineProbe.js` | 实际使用的设置页在引擎分类下提供单引擎「测试配置」及五引擎「一键测试并排序」；后者会发真实请求并使用本轮时限/动态文本，**不计翻译历史成功率**。单引擎测试的 Google 调用当前不显式传入翻译时限；新增可选代理需同时明确这两种测试如何使用快照配置，不应静默更改其他引擎。遗留 `src/Settings/index.vue` / `SettingsPanel.vue` 不参与实现。 |
| `src/Translate/utils/storage.js`、`useSettings.js` | 设置以单个 `dev-translation-settings` key 持久化，`DEFAULT_SETTINGS` 添加新字段即可进入默认配置；加载时已有旧配置迁移及超时规范化，不能改坏。设置保存会返回布尔结果，应对失败给出安全反馈。 |
| `src/Translate/utils/logger.js`、`safeLog.js`、`engineStats.js` | 日志只接收白名单元数据（类别、状态码、阶段等），旧记录读取时还会清理。Google 来源级诊断需要扩展**受控枚举字段**或在同等安全层处理，不能直接记录异常对象、请求 URL、查询参数、代理地址或译文。历史统计只对一级 Google 真实尝试记一次 success/failure，跳过不进分母。 |
| `scripts/preload-bridge.test.cjs`、`scripts/engine-bridge.test.mjs`、`scripts/engine-probe.test.mjs` | 已有 Google 三源总预算、取消、共享 inflight、一级故障转移及探测的隔离用例；新增改造应先写复现用例，再做实现。`pnpm test` 不依赖真实外网；`pnpm build` 需保留解引用的 `dist/preload/node_modules/google-translate-api-x` 真文件。 |

**调研依据（截至文档时间）**：

1. 本地锁定 `google-translate-api-x@10.7.3`（`package.json`、`pnpm-lock.yaml`）。其本地 `index.d.ts` 中 `forceBatch` 默认为 true、`fallbackBatch` 表示 **single 失败转 batch**，不是目前 `forceBatch: true` 所使用的另一重自动兜底；库提供 `requestFunction` 与 `requestOptions` 供传输层定制。见 `node_modules/google-translate-api-x/index.d.ts`、`lib/translation/translate.cjs`、`lib/translation/batchTranslate.cjs`。**不能简单再打开 `fallbackBatch` 并声称提升成功率**；改源顺序/代理实现须在实际 uTools Node 运行时核对库 fetch 与 Node HTTPS 两条路径的代理支持和取消行为。
2. 官方 Google Cloud Translation 的鉴权及配额与本项目免密网页端点**不是同一种接口**；本次不接入前者，不套用其 SLA、配额数字或成功保证。参考 [Google Cloud Translation 鉴权](https://docs.cloud.google.com/translate/docs/authentication)、[配额](https://docs.cloud.google.com/translate/quotas)；库源码 [google-translate-api-x](https://github.com/AidanWelch/google-translate-api)。
3. [第三方对免密接口 429/响应变化的复现记录](https://github.com/artemave/translate_onhover/issues/74) 提示可能有网络/IP 与格式波动，但**只是风险案例，不是该用户报错的诊断证据**。代理仅能改变可达路径，不能保证绕过服务端限制或长期稳定；记录来源级失败类别、基线和环境后再决定是否需要额外冷却/轻量重试。

## 3. 已确认功能需求

- **REQ-001｜成功口径与先诊断**：只有 Google 在自身时限内返回有效非空译文才计为 Google 成功；其他一级引擎回退成功不改变 Google 此次 failure。实施前保留**当前仓库改动前版本**的可运行安装包供手动对照，并准备 30 条不重复、非敏感的中英短句固定样本；先通过不泄密的来源级诊断区分 `library` / `gtx` / `clients5` 的超时、网络失败、HTTP 状态、解析失败、空结果及代理连接失败。现有截图的打包堆栈只作线索，不作为根因结论。
- **REQ-002｜免密直连分时切源**：代理未配置/关闭时继续使用现有三个 Google 来源，单个慢来源不得独占整段 Google 预算；为后续来源预留有意义的试探窗口，提前成功立即返回，提前失败将未用时间让给后续来源。Google 总耗时仍受本轮 `engineResponseTimeoutSeconds`（默认 5 秒）及外层调度器约束；预算耗尽不再启动新源。对网络瞬断或可恢复失败可做**有界**重试/切源；429 不立即对同源连环重试，超时/取消后的迟到结果不得再写缓存或统计。
- **REQ-003｜可选自填代理**：在当前设置页引擎分类的 Google 配置区提供默认关闭的开关和用户自填代理地址，仅接受**无用户名密码的 `http://` 或 `https://` HTTP(S) CONNECT 代理**，不支持 SOCKS5；非法、空白（启用时）或含凭据地址不保存为有效启用配置，告知安全原因。启用后所有 Google 来源的联网请求（包括库的 batch 与两个直接端点）应优先走该代理；设置页单项测试、批量测试和普通翻译使用同一生效规则。其他引擎及词典不通过此 Google 专用代理，默认不读取或覆盖系统代理配置。代理地址须经设置持久化，重进插件仍生效；保存失败不虚报成功。
- **REQ-004｜代理失败回退直连**：用户启用代理后，优先通过代理尝试；代理不可达/握手失败/请求失败且本轮还有预算时允许尝试直连，**提前预留直连预算**。代理与直连合计仍只有一段 Google 总时限，不叠加成双倍；若代理和直连均失败，给出可操作、脱敏的失败原因以及检查代理/切换一级引擎提示。界面须说明“代理故障可能直连 Google”，以免用户误以为绝不会直连。
- **REQ-005｜日志与统计安全**：来源级信息仅记录来源枚举、路径枚举（代理/直连）、错误类别、可用的 HTTP 状态和粗粒度耗时等最小字段；扩展 `safeLog.js` 的白名单及读取迁移测试，不记录原文、译文、请求 URL/查询参数、代理主机地址、用户名密码或第三方响应正文。已安装版本的原始调用栈不复制进程序日志。每次正式 Google 一级调用仍最多结算一次成功/失败，设置页测试仍不写历史统计。
- **REQ-006｜兼容性与取消**：保留 Google 24h LRU、同 key inflight 去重、有效等待者不被其他等待者超时中断、旧请求/旧设置快照不污染新请求。支持取消的库 fetch、Node HTTP 请求在超时/无等待者时实际释放；保持 `window.services` 初始化在库缺失时也不失败、preload 为 CommonJS、构建产物依赖是真文件。现有一级 524 回退、词典与其他引擎行为不变。

## 4. 技术方案（实施建议；具体代码结构可调整，不将建议冒充实测结论）

1. **建立可归因的失败模型**：保留 `translateWithSources()` 的来源标识和有限错误分类，避免只剩最后一次错误导致三源被总错误遮蔽。把受控枚举和安全字段传递至 Google 总失败的诊断出口；一级仍抛一个可由 `classifyError()` 分类的安全错误，新增来源诊断与最终 Google 计数分离。设置页「高级」可看到脱敏的分来源诊断摘要，不打印底层异常 `cause`。确认已安装包与当前源码版本一致性，否则以仓库改动前构建为对照基线。
2. **预算调度**：在一次 Google 调用内按剩余绝对截止时间分配每段尝试，先为后续直连来源保留时间；配置代理时再为代理失败后的直连保留时间。推荐对默认 5 秒采用“前段有上限、失败后剩余可借用”的可测试策略（例如代理阶段最多占约 3 秒，至少约 2 秒留给直连；直连阶段按 3 个来源分配初始上限），**不是增加一级超时，也不是承诺每一源都必然成功**。实际分配可用同等效果的算法，但必须以挂起首源、挂起代理的隔离用例证明后继至少会被尝试，且外层不会多次结算。429 对同来源本轮不立即重复；网络错误可依剩余预算切另一来源。
3. **统一 Google 专用传输**：两个 `https.get` 来源使用兼容当前 uTools Node 版本的 CONNECT agent；库来源利用其 `requestFunction`/兼容的 fetch 代理实现注入，先验证 batch 请求确实穿过代理、信号/截止继续生效。不要假定把 Node `https` agent 直接放进内建 fetch `requestOptions` 就会生效。代理连接建立与 TLS、响应解析都受该段时限约束；不要通过渲染组件直接 `fetch`，不要为代理开放任意目标转发；仍只请求已列 Google 主机。失败时及时销毁 socket/abort，避免代理断连积累未清理连接。新依赖（如有）按 pnpm 管理并确认 dist 解引用打包；保留库可选性。
4. **设置与并发**：在 `DEFAULT_SETTINGS` 添加独立 Google 代理字段，在 `loadSettings`/保存时校验协议、凭据、空值并兼容旧配置；保存前快照可用配置，在调用中途修改代理仅影响后续请求。缓存/共享 inflight 的路由语义需隔离（代理配置与直连策略改变不能错误复用旧正在运行的连接）；相同请求共享时，单个等待者超时不终止其他有效等待者。缓存命中仍算有效译文，但基线/代理路由验收必须使用冷缓存与新文本，避免错误判定 CONNECT 路由或成功率。
5. **最小 UI**：现用 `SettingsPage.vue` 的 Google 详情展示可选代理、风险提示、设置保存反馈，适配浅/深色及小窗口；其余引擎 UI 和输出开关仍按现状。不要修改无引用遗留文件。若实现前发现 uTools 的 Node 版本或库接口无法满足代理、取消与打包要求，先提出具体验证证据并请用户决策，**不能偷偷改为付费 API/公网中转或宣称已实现代理能力**。

## 5. 实施步骤（供后续 Harness，**本次均未执行**）

1. 核对 uTools 开发插件、已安装包与仓库版本；保留改动前可运行包，给用户 30 条固定、非敏感样本和冷缓存操作步骤。先新增可控 mock 的失败复现用例：首来源挂满现有 5 秒、不同来源分别返回超时/429/解析错误、代理 CONNECT 失败及旧截图只有总错误无法区分来源；用例应在修改实现前暴露问题。**不要以无外网隔离测试宣称线上成功率改善。**
2. 在 preload 实现来源级安全分类、限时切源与代理/直连预算；对 429、其他 4xx、5xx、超时和网络错误设定有界路径并清理连接；保持库缺失时桥接可用。
3. 接入 Google 专用代理设置、校验、持久化和 UI 提示；扩展受控日志元数据白名单/读取清理；通过可控本地 CONNECT 代理在隔离用例断言三条来源的确过代理、故障回退直连且 Google 总预算不超时。
4. 补充缓存/inflight、配置切换、晚到拒绝、空译文、一级只计一次、设置页单项/批量测试不污染统计、旧设置迁移和构建真文件的回归用例。项目常用命令为 `pnpm test`、`pnpm build`；这是后续实现与自检建议，**不改变下述用户手动验收责任，也不代表本次执行过这些命令**。
5. 完成实施后按下节给出可直接执行的 uTools 手动验收指引和记录模板；用户分别核对开发形态（项目根目录 + `pnpm dev` 的 5175）及如需确认安装形态时的 `dist/`，不可当成同一插件实例。

## 6. 验收操作、标准与责任

**用户将手动验证，Harness 无需执行自动化验证，完成实施并给出手动验证步骤即可。** 下列操作由用户在后续实施完成后手动执行；Harness 不得把设计中的测试或未做的线上测量写成已通过。成功率指标仅对**Google 可达**的可比网络成立；对于所有 Google 来源均被阻断且无代理的网络，验收以清晰失败反馈与可选代理路径为准，不虚报 +10 个百分点。

- **AC-001｜可比较基线（手动）**：保留实施前**本仓库**构建的旧版作为 A，新版作为 B；在同一台设备、相同网络/相近时段、相同 `engineResponseTimeoutSeconds`（默认 5 秒）、同一方向配置和同一组 **30 条不重复中英短句**上各翻译一次。每次使用冷缓存（重载相应插件实例、先确认不是 24h 热缓存），Google 设为 P1，逐条记“Google 自身返回非空译文 = 1，否则 = 0”，即使其他引擎回退成功也记 Google = 0；记录 A/B 结果、网络是否可达、日期和错误类别，不存敏感原文。A 的可达网络 Google 成功数 `A≤27` 时 B 至少成功 `A+3` 条（提升不少于 10 个百分点）；`A>27` 时 B 不少于 A 条。若 A/B 所处网络状态变化明显，或 Google 完全不可达，标为**不可比/未达成量化验收**，在同等可达条件下重测，不得将不可比数据当作通过。
- **AC-002｜首源阻塞与总时限（手动辅助可控环境）**：在可控网络/代理模拟首个来源挂起及代理 CONNECT 挂起，Google 总预算设为 5 秒；能从脱敏来源诊断确认仍有后续来源/直连被尝试，且 Google 没有等到多个 5 秒叠加才进行一级回退（允许少量事件循环误差）。首源快速成功时无多余请求；三个来源均失败时只有一次 Google 一级失败，下一引擎仍可按原顺序兜底。
- **AC-003｜代理路由与回退（手动）**：设置一个用户控制、无认证、可记录 CONNECT 次数的 HTTP(S) 代理并启用；冷缓存测试至少 3 条新短句，代理侧确有对应 Google 目标的 CONNECT 记录且插件返回 Google 译文；断开代理再用新文本请求，若直连网络可达则剩余预算内直连成功，否则收到安全失败反馈、无卡死和异常持续请求。界面明确说明代理失效可能直连，关闭代理后仅走直连。若直连本就不可达，不以代理断开后的 Google 成功作为验收前提。
- **AC-004｜设置与安全（手动）**：默认关闭；合法无认证 `http://` / `https://` 代理可保存、重进仍生效；空地址（启用时）、`socks5://`、带用户名密码、畸形 URL 均不成为有效启用配置。设置页测试配置、批量测试与正式翻译遵守代理配置，但测试不增加正式翻译成功/失败历史计数。高级日志/复制日志/失败弹窗不出现原文、译文、代理地址/凭据、Google 完整 URL、上游响应正文或用户提供的打包堆栈；日志能区分来源、代理/直连与安全错误类别。
- **AC-005｜兼容与极端失败（手动）**：无代理的普通翻译、一级 524 故障转移、词典异步补充、快速重复翻译及清空输入按原行为；无 Google 网络时错误不长时间转圈，仍可切其他引擎并收到代理可选提示；库缺失时其他 `window.services` 方法仍可用。开发与安装形态不要相互代替，且不得将旧已安装包错误堆栈直接当成新版回归通过或失败的证据。

**记录模板**：环境/日期；旧版仓库构建标识、新版标识；Google 时限及网络可达性；30 条 A/B 成功数和主要安全失败分类；代理 URL 仅记录“已配置/未配置”，不写主机；CONNECT 是否观察到；AC-002～005 各项“通过/失败/因环境未测”。任一可执行且适用的标准未通过时，不应声称本需求已被验证达成。

## 7. 风险与待确认事项

- **主要风险：无法保证外部免密接口可用**。若国内网络三个 Google 目标均不可达或上游调整格式/限制，分时切源也不创造网络连通性；代理必须由用户自行选择可信服务，代理运营者可看到所连接的目标，连接安全及隐私取决于代理/TLS 环境。没有可用可控代理时 **AC-003 无法人工执行，应记录“未测”，不得假报通过**。
- **指标风险**：30 条样本的 +3 条容易受网络波动影响；高基线使用不下降规则。实施后若反复在可达且可比的环境仍未达到阈值，应带脱敏失败分布重新诊断并与用户讨论范围，不能把其他一级引擎的成功、缓存热命中或代理网络的结果混入无代理直连对比。
- **实现风险**：库 fetch 与 Node `https.get` 代理配置方式不同；uTools Electron/Node 版本、HTTPS 代理证书、打包解引用、`AbortController` 与共享 inflight 的竞态必须实际核验。HTTP(S) CONNECT 代理是用户输入的目标，不可记录地址/拼接明文凭据；不可借此绕过其他引擎流量策略。
- **剩余非阻塞待确认/实施期证据**：用户尚无同次失败的脱敏来源日志、统计基线或旧已安装包与当前仓库版本对应关系；需要后续按 AC-001 采集并以现场证据校准失败原因。代理服务地址由用户在手动验收时自备；若无法提供，代理验收保持“未测”。除此之外，目标、代理范围、无代理边界、5 秒总时限、量化阈值和验收责任均已由用户确认，不得把待采集证据写成已确认事实。
