# 翻译引擎桥接故障排查与修复：需求与实施文档

> 状态：**已实施代码**（仓库版本 1.4.1）。实施记录、产物核对与 uTools 重装/手动验收步骤见 `docs/2026-0929-翻译引擎桥接-实施与验收.md`。本文件仍是需求与验收依据；最终安装入口验收由用户完成。

## 1. 背景与目标

已安装在 uTools 中的插件一次翻译按顺序遇到：uTools AI 的自定义模型 `deepseek-ai/deepseek-v4-flash` 返回 `524 status code (no body)`；DeepLX、Google、DeepL 均报“不可用”；自定义 AI 报 `Cannot read properties of undefined (reading 'requestThirdpartyAI')`；最终显示“所有引擎均失败”。另一次日志中 Google 与自定义 AI 重现同类错误。已确认报错来自**已安装插件**（日志指向 `.asar/assets/…`），并非当前开发插件运行时。用户负责在 uTools 内进行最终手动验收。

目标：找到并修复**已安装实例中 preload 桥接缺失**的真实原因，使依赖 `window.services` 的引擎在有效配置下可正常调用；上游 524 不阻塞回退；不可用项被有依据地跳过，全部失败时反馈可操作原因；统计区分实际调用与跳过；新旧日志满足最少元数据原则；交付可核对的构建/打包产物与用户重装、手动验收指引。

非目标：修复 uTools 自定义模型或其上游网关的 524、承诺外部翻译服务始终可用、增加新翻译引擎、替用户发布到市场或在本次文档任务中修改代码/生成安装包。524 仅表明这次调用返回该状态及无响应体，**不能凭日志证明具体网络根因**。

## 3. 功能需求

- **REQ-001 根因定位与产物一致性**：先确认 uTools 实际打开的是哪个插件实例、版本、清单与入口；对照已安装包、重新构建的 `dist/plugin.json` / `dist/preload/services.js`、CommonJS 依赖及 preload 首个异常，记录证据后修复真实加载或打包原因。若源码和安装包不一致，纳入重建、打包及重装指引；不得以仅在开发插件存在 `window.services` 宣称修复已安装版本。
- **REQ-002 桥接完整性**：成功加载的实例应有完整且可调用的桥接方法；缺失、部分缺失或初始化异常时不得抛 `undefined` 属性访问错误。翻译页、设置页测试与获取模型列表使用一致的安全检查；若确需变更 preload，仍为 CommonJS、联网请求仍在 preload。
- **REQ-003 回退与跳过**：保持用户配置的引擎顺序及首位主引擎；未配置必要凭据/地址、或依赖的 preload 方法不可用时按原因跳过并尝试后续引擎。`window.services` 整体缺失时多个 preload 引擎均跳过，若 uTools AI 可用仍可出结果；仅在当前引擎真实发起请求且失败时计一次服务失败。部分缺失只影响对应方法；词典等可选能力失败不得把已成功的主译文误报为失败（实施时明确词典降级策略）。
- **REQ-004 524 行为**：uTools AI 返回 524（无响应体）时不对同引擎自动重试，按顺序直接回退；不混淆为插件 preload 故障，不保证该模型恢复。非 524 的引擎失败沿用顺序回退；过期请求、清空输入和卸载时不继续陈旧回退或覆盖新结果。
- **REQ-005 用户反馈**：有后备引擎成功时保持译文及成功引擎标识，告知发生回退；桥接整体缺失时给出简洁可操作的重载/检查安装版本提示，不暴露 TypeError。所有可用引擎失败时展示归因摘要：优先说明共同阻断因素（桥接未加载、均未配置），否则说明可用引擎调用失败；保留重试入口，避免机械呈现最后一个引擎异常或原始响应正文。
- **REQ-006 独立跳过统计**：每引擎新增可展示的“跳过次数”，至少区分内部的环境缺失与配置缺失原因；成功率、近期窗口和“按稳定性排序”只以**实际调用**成功/失败为分母，跳过不污染成功率。读取旧统计数据时缺省跳过数为 0，保留原成功/失败和顺序；清空统计时一并清空跳过数。
- **REQ-007 最少元数据日志及历史治理**：新日志只保留引擎、错误类别、状态码（若有）、阶段、必要的去标识请求序号/时间等；不保存原文、prompt、请求体、凭据、token、完整 URL、URL 查询、响应正文和可能携带这些信息的原始堆栈或异常 message。日志展示、复制、系统全失败记录与设置页测试的错误展示采用安全消息。旧日志在读取/复制前或迁移时安全清理：无法确信脱敏彻底的旧 `detail` 或敏感消息应删除而非原样保留；保持日志保留天数及条数上限，不输出原始秘密到控制台。
- **REQ-008 交付与验收**：实施者交付代码修复、可复核的构建产物和适用于已安装插件的本地打包/覆盖安装说明，不代用户市场发布；提供隔离故障用例及 uTools 手动核验步骤。真实 524 上游恢复不作为验收必要条件。

## 4. 技术方案（待证据驱动，不预断根因）

1. **复现先行**：记录安装实例的版本/入口/manifest 指向、`window.services` 各方法是否存在、preload 首条加载错误；比较 `public/`、新 `dist/` 和最终安装包的清单、preload 文件及依赖。重点排查：安装包遗漏 `preload/services.js`、相对路径不匹配、顶层 `require` 失败、preload 初始化中断、安装包陈旧或打开了另一实例。这些都是排查假设，**非已确定结论**。在修复前编写最小可复现的隔离验证用例/步骤；问题不可稳定自动化时记录实际复现证据。
2. **修复加载链路而非假注入**：根据首个真实错误修复依赖解析、产物收集或 preload 初始化；不得在渲染进程伪造空 `window.services` 掩盖加载失败。保持 `public/preload/package.json` 的 CommonJS 边界、`public/plugin.json` 与 `dist/plugin.json` 的正确相对路径，核验运行时所需依赖的安装包解析。再对消费端统一做能力检查，检查到方法不可用时返回结构化“环境跳过”原因。
3. **显式分类调度结果**：将 `success`、`failure`（已发出真实调用）、`skipped`（未配置/缺方法）区分；单个桥接缺失尽量只记录一次环境原因，不对四个引擎刷相同原始异常。保持 failoverOrder 不变，记录各项诊断供最终归因；524 属于 `failure`，立即尝试后继项。请求令牌校验覆盖跳过、异步返回和异常分支；兼顾单词词典查询的桥接缺失处理。
4. **统计兼容与展示**：扩展 `engineStats.js` 的存储结构及 `SettingsPage.vue` 的展示，以旧对象字段默认值向后兼容；`total = success + failure` 维持现有成功率语义，`skipped` 独立于 total/recent，跳过原因仅保留非敏感类别。配置页手动测试报错不得污染翻译统计，除非既有业务原本记录（当前未记录）。
5. **日志安全收口**：在产生日志、持久化、读取/复制边界统一采用白名单安全字段；处理 `services.js` 的诊断上下文、`index.vue` 的失败记录和 `SettingsPage.vue` 的报错显示。旧记录的敏感明细及不能可靠判别的消息在读取/迁移时清除，避免“只在显示时隐藏，复制仍泄露”；必要时清理不可信 `detail`，保留安全的时间/等级/引擎。用户可见提示为预定义分类文案，不直接使用含正文的原始 `err.message`。
6. **产物闭环**：`pnpm build` 后核验 `dist/` 下清单与 preload 完整、依赖可解析，按实际 uTools 本地安装/打包流程形成可复核产物；将新旧版本识别及重新安装/重载步骤交给用户手动验证。仓库没有既存 upx 打包脚本，实施时先确认实际打包方式，不能臆造命令或把旧 `dist/` 当作新验收证据。

## 6. 验收标准

- **AC-001**：在用户的已安装插件入口核对版本与实际 manifest；新打包产物与新 `dist/` 的 preload 文件路径、内容、依赖可核验，uTools 控制台无 preload 初始化异常；调用前 `window.services` 具备预期方法。开发服务器单独可用不构成通过。
- **AC-002**：模拟 `window.services = undefined` 和缺单个方法时，在翻译页、设置页测试及模型获取均不抛属性读取 TypeError；preload 相关引擎按缺失范围跳过，uTools AI 可用时仍能成功翻译并提示；缺失原因可在安全日志中辨识。
- **AC-003**：配置有效且桥接正常时，受控的 Google、DeepL、DeepLX、自定义 AI 调用分别能到达对应 preload 方法；模拟其中一个失败仍按配置顺序继续，成功结果标识正确，不改变旧用户排序。
- **AC-004**：受控模拟 uTools AI 抛出 `524 status code (no body)`，同一翻译请求中 AI 调用恰好一次并立即尝试下一已配置且可用引擎；上游实际仍为 524 不导致本条验收失败。
- **AC-005**：配置缺失或环境缺失的项不发真实网络请求、不计 `failure`/`total`/近期样本，而对应 `skipped` 增 1；真实调用失败才计失败。旧统计兼容、跳过数可见、排序只根据实际成功率，清空统计有效。
- **AC-006**：全部后备项跳过或均失败时，UI 显示可操作归因摘要和重试按钮，不显示原始 TypeError、最后一项无关异常或服务端原始正文；无健康引擎时不承诺译文成功。存在健康后备项时译文和降级提示可见。
- **AC-007**：使用含测试原文、prompt、伪 Key、URL token/查询及响应正文的失败样例，验证日志存储、日志查看/复制及相关 UI 提示均不出现这些字符串；读取历史敏感日志后同样不泄露，最多保留安全元数据。诊断仍能区分 `524`、桥接缺失、未配置和实际 HTTP 失败。
- **AC-008**：反复触发重试、快速更换输入、清空及卸载时，旧请求不得继续覆盖新结果或产生错误归因/重复统计；单词词典桥接缺失不得破坏已成功主译文。
- **AC-009**：`pnpm build` 通过，实施者提供构建/打包产物核对结果和用户的 uTools 重装与手动验收步骤；用户在真实安装入口完成最终验收。若无可用外部引擎，以隔离替身验证回退及桥接、以真实环境验证 preload 加载，不伪称外部服务已恢复。

## 7. 风险与待确认事项

- **运行时根因待取证**：目前只有安装版日志，尚未读取该安装包的清单/preload 加载错误；源码声明 preload、旧 `dist` 有文件不等于安装版成功加载。若安装包属于旧版本，修源码仍须重建/重装才生效。
- **打包工具/方式待实施时核对**：仓库无打包脚本；实际 upx 生成流程及运行时 Node 模块查找行为必须以用户环境/工具实际结果为准，不能预写确定命令。
- **上游不稳定**：524、Google/DeepL/DeepLX 的真实网络及配置可用性不能由这段日志验证；隔离验收与用户真实服务验收分别记录。
- **历史隐私与兼容**：旧日志可能含原文/令牌，保守清除不安全字段将损失旧明细；旧统计的成功率已受以往桥接缺失失败次数影响，本次保持旧计数、不静默重算历史事实，必要时由用户主动清空统计。
- **未决产品决策：无**。实施阶段尚需完成上述环境取证；若实际根因超出桥接/打包范围，先反馈证据与影响范围，再决定是否扩展需求，不把推测写成既定修复。
