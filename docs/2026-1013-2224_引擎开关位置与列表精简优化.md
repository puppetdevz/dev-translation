## 1. 背景与目标

### 1.1 背景

现有引擎列表同时承载图标、名称、AI/MT 标签、状态、滑动开关和优先级，信息密度过高。截图中开关挤占名称与标签空间，形成突兀的纵向控制列。用户希望将开关移至右侧配置详情标题栏，在「测试配置」左侧集中放置当前引擎的操作。

### 1.2 目标

1. 删除列表开关与 AI/MT 标签，改善名称可读性及视觉层级。
2. 在详情标题栏提供唯一的「启用引擎 + 滑动开关」，仅控制当前选中的引擎。
3. 保持列表选择、拖拽、状态识别和配置维护能力，兼容深浅色及窄窗口。
4. 完整复用已有启停、持久化与异常规则，避免布局调整引入业务回归。

### 1.3 非目标

- 不新增引擎、总控开关、批量启停、自定义 AI 组级开关或确认弹窗。
- 不改变 AI/MT 固定分类；删除的是列表可见标签，而非共享类型定义。
- 不改变主引擎定义、有效顺序、翻译故障转移、AI 辅助任务、词典补全、统计或日志规则。
- 不根据配置是否完整、测试是否成功自动启停，不新增网络请求。
- 不重构整个设置页，不改变分类入口、开发端口、插件清单或路由。
- 不发布，不修改版本号或 `CHANGELOG.md`。
- 本轮不得改代码或既有文档，不创建本文以外的文件。

## 4. 技术方案

### 4.1 模板与状态绑定

1. 删除 `.engine-card` 内的开关节点与 `.engine-kind-tag` 节点，保持 `.engine-card-info`、状态区及优先级节点。
2. 在共享 `.engine-config-header` 中新增操作容器，例如 `.engine-config-actions`，依次放置开关组合与原测试按钮。
3. 直接绑定已有计算值与处理函数：
   - 激活样式和 `aria-pressed` 使用 `selectedEngineEnabled`。
   - 点击调用 `toggleEngineEnabled(selectedEngine)`，不绑定 `mainEngine` 或列表索引。
   - 可访问名称沿用「当前引擎名称 + 引擎开关」语义；title 随状态显示现有开启/关闭说明。
   - 保持 `type="button"`、原有滑块结构及阻止意外拖动的属性；点击只执行一次更新。
4. 「启用引擎」是固定可见标签，不随状态切换为另一套文案；使用标签关联或可访问名称建立控制关系，避免做成第二个重复启停按钮。
5. 不新建本地布尔 ref、不新增 watch 复制状态、不新增设置字段；复用 `selectedEngineEnabled` 可避免编辑焦点切换时状态滞后。
6. 保留共享头部所在的 `:key="selectedEngine"` 内容切换结构，确保任一引擎进入详情后都能操作。

### 4.2 样式与响应式

- 名称区使用 `min-width: 0`；操作容器使用横向 flex 和明确间距，标签/开关组合不拆行。
- 优先复用现有 38×22px 开关规格，尺寸与间距是实施细节，不要求截图像素级复刻。
- 操作区可作为不可拆分的整体换行；容器宽度不足时让名称行和操作行分层，不把测试按钮挤出可见区域。换行不能仅依赖 ≤640px：宽窗内部详情区不足也应正常降级。
- 不新增无意义大块留白或扩大列表宽度补偿旧拥挤问题；列表正常项没有状态时不强制占一行空白。
- 核对深色下标签、开关关闭态、边框、焦点和测试按钮对比度。新动效若需要，仅用 transform/opacity。
- 删除 AI/MT 后，检查 `.engine-kind-tag` 相关浅/深色样式及 `engineKindLabel` 导入是否已无引用；仅清理本组件中的无用代码，不删除共享分类 API。
- 列表不再含开关后，可以清理 `onDragStart` 中仅针对列表开关的死保护，但必须保留正常拖拽逻辑；右侧开关不属于可拖拽卡片。

### 4.3 保持既有业务接口

调用链保持：`toggleEngineEnabled(selectedEngine)` → `setEngineEnabled(...)` → `persistSetting('engineEnabled', next)` → `updateSetting(...)` → `saveSettings(...)`。

不应改动 `engineAvailability.js`、`engineBridge.js`、`aiTaskFailover.js`、翻译页任务 watcher 或 preload 网络服务。关闭提示、未配置提示、测试 loading/错误展示继续使用已有实现。自定义 AI 仍是整条组链的一个总开关。

### 4.4 过时测试与说明的同步

未来实施时，调整 `scripts/component-regressions.test.mjs` 的布局断言：列表不含开关/类型标签，详情头含唯一开关、可访问状态及当前选中项调用；保留主引擎、全关、保存失败等业务断言。若清理旧拖拽分支，应同步取消对该死分支的强依赖，保留「右侧启停不改排序、列表拖拽可用」的有效覆盖。

同步测试定义不等于必须运行自动化验证；**按用户确认，自动化命令不是本次后续实施的验收门槛**。不要为让旧测试成立而保留隐藏开关或废弃类型标签。若后续发现新缺陷，遵循仓库的缺陷复现优先规则，不借 UI 任务扩大业务改造范围。

## 7. 风险与待确认事项

### 7.1 风险及应对

- **控制对象混淆**：有效主引擎不等于编辑焦点。必须绑定 `selectedEngine`，避免开关误操作主引擎。
- **长名称与操作区挤占**：移到详情头后仍可能窄窗溢出，应以可用空间整体换行，而非依靠隐藏操作或过度缩小控件。
- **过时断言阻碍迁移**：现有静态用例写死旧布局。应同步新布局语义，而非保留隐藏旧节点或无用分支迁就测试。
- **类型删错层级**：只删除列表 AI/MT 展示及本组件无引用样式/导入，共享固定分类与自动路径筛选不能删除。
- **失败后状态误导**：保存失败继续沿用内存生效策略，必须保留提示，不能添加未确认的回滚行为。
- **关闭误解为断网**：在途任务按旧快照继续，手动维护可能真实请求且产生费用；保留现有关闭说明，不宣称关闭后绝无请求。
- **历史文档冲突**：本文只覆盖布局要求，不推翻旧业务需求，不把旧验收记录当作新布局已验证证据。
- **宿主与打包差异**：开发可用不代表 `dist/` 可用；验收环境和不可执行项目须据实记录。
