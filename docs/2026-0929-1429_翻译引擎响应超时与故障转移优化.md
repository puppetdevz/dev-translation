# 翻译引擎响应超时与故障转移优化：需求及实施方案

> 文档时间：2026-09-29 14:29（本地时间，CST）  
> 状态：已按本文实施（设置字段、调度超时、Google 三源预算、词典解耦）；`pnpm test` / `pnpm build` 已通过。uTools 开发插件与 `dist/` 安装形态的手工验收见 `TESTING.md`。

## 1. 背景与目标

翻译目前按用户配置的故障转移顺序逐个尝试引擎；慢响应会拖延切换。用户要求：**每个引擎在可配置时限内未取得主译文，就作为真实故障，立即尝试下一个可用引擎**。默认 5 秒，五种引擎行为一致；减少因等待故障引擎造成的延迟，同时保留成功译文、现有回退提示与稳定性统计语义。

**非目标**：不更改引擎优先级/并发策略（仍串行）、不对同一引擎自动重试、不承诺整次翻译在 5 秒内结束；不让本配置影响 AI 语言检测、润色、设置页引擎测试、模型列表获取或词典请求本身的超时；不新增网络请求到渲染进程，不更换翻译源，不修改其他功能的提示词或接口。

## 2. 现状与涉及模块

| 模块 | 已核对的现状及影响 |
| --- | --- |
| `src/Translate/index.vue` | `translate()` 调 `runEngineFailover()`；`translateWithEngine()` 路由五种引擎；成功/失败/跳过分别记录统计及安全日志，成功后显示译文、引擎徽标与回退提示；`translateRequestId` 阻止旧请求回填。uTools AI 的翻译调用目前没有统一的引擎级时限。Google/DeepL/DeepLX 单词模式会等待可选词典数据后才返回结果。 |
| `src/Translate/utils/engineBridge.js` | `runEngineFailover()` 串行逐项 `await translateWith(engine)`，没有整个引擎尝试的超时；524 及其他真实失败会转下一引擎，缺方法/配置则跳过；`classifyError()` 已有 `timeout` 类别。 |
| `public/preload/services.js` | 联网引擎均在 Node preload，经 `window.services` 暴露。普通 HTTP helper 默认 5000 ms；**自定义 AI 翻译 POST 单独传 30000 ms**。Google 有三源串行轮换，每源可能各等 5 秒，且有 24h LRU 缓存与同 key inflight 去重。部分 HTTP 定时器到点只 reject，需核查并释放底层请求；Google 库源已有 `AbortController`。词典查询有独立超时。 |
| `src/Translate/utils/storage.js`、`src/Translate/utils/useSettings.js` | 设置在 `dev-translation-settings` 下存储，`DEFAULT_SETTINGS` 合并旧设置；`useSettings()` 为共享 reactive 单例，`updateSetting()` 保存配置。旧设置迁移（包括 `failoverOrder` 和 DeepL/DeepLX）须保留。 |
| `src/Translate/components/SettingsPage.vue` | 当前真正使用的设置页；故障转移排序区域适合加入共享时限输入。设置页另有单引擎连接测试和模型列表获取，不能误接入本次翻译超时。 |
| `src/Translate/utils/engineStats.js`、`logger.js` / `safeLog.js` | 真实调用失败计入 failure/recent；环境/配置跳过不计成功率。日志只存安全分类及最小元数据。 |
| `scripts/engine-bridge.test.mjs`、`scripts/preload-bridge.test.cjs`、`scripts/engine-stats.test.mjs` | 已覆盖桥接跳过、524 回退、过期回填、桥接初始化和统计；尚需增加本次引擎级时限、取消、设置及词典晚到的针对性测试。 |

运行约束：preload 为 CommonJS；渲染进程只通过 `window.services` 调用联网翻译；保留 Google 缓存/去重、524 立即回退和现有安全日志规则。`src/Settings/index.vue`、`SettingsPanel.vue` 为遗留无引用组件，不作为实施入口。

## 3. 已确认功能需求

- **REQ-001｜统一设置**：在现用设置页的故障转移区域提供一项全局“翻译引擎响应超时（秒）”；允许 **1–60 的整数**，默认 **5 秒**。老用户缺字段、存储值为空/非整数/越界时使用 5 秒，设置页展示规范化后的有效值；有效值持久化并在重新进入插件后继续生效。不得破坏已有设置与迁移。
- **REQ-002｜作用范围**：仅点击翻译及重试的故障转移链受本设置约束。五种引擎 `ai`、`thirdparty-ai`、`google`、`deepl`、`deeplx` 均适用；非翻译操作沿用现状。一次翻译开始时固定有效超时值，中途修改只对下一次翻译生效。
- **REQ-003｜计时语义**：每个**已准备好并真正调用**的引擎从开始尝试至取得可用主译文，各自有一次独立的时限（包含必要的响应解析）；不足以得到可用译文即超时。未配置/桥接缺失仍跳过，不占用调用失败统计；后备引擎有自己的完整时限。边界上只允许一次成功或一次失败结算，不得同时计两次。
- **REQ-004｜超时故障转移**：引擎超时标为 `timeout` 类真实 failure，**不对同一引擎重试**，直接按 `failoverOrder` 尝试下一已配置引擎；524 继续立即回退。后备成功时继续显示译文、实际引擎标识和现有回退提示；全部失败时使用安全、可操作的现有归因摘要和重试入口，不暴露 URL、正文、密钥或原始异常。真实超时每引擎每次尝试仅记一次失败/一条相应安全错误日志，跳过仍不计入成功率。
- **REQ-005｜Google 总预算**：Google 三源仍按当前顺序内部轮换，但**共享一次 Google 引擎的剩余时间**；某源提前失败则在剩余时间内试下一源，不能让每源各用满配置时限。总预算耗尽即回退到下一顶级引擎，未耗尽且某源成功则返回译文。保持缓存与 inflight 去重；避免一个已超时的等待者取消另一个仍有效的共享请求。
- **REQ-006｜取消及晚到保护**：达到时限即允许调度器回退；可取消的 Node HTTP/Google 请求尽量取消并释放资源。对于可能无法取消的 `window.utools.ai` 或其他调用，应隔离其晚到结果/错误，不能覆盖后备译文、新请求，不能再记录成功/失败或触发未处理拒绝。重新翻译、清空输入或卸载后的旧回调亦须遵守当前请求保护。
- **REQ-007｜词典独立**：主译文成功即判该引擎成功；单词词典慢/失败不触发超时回退，不推翻主译文，也不延迟主译文的展示。词典结果随后到达时仅可补充**仍然有效的同一译文**的音标/释义/例句；失败沿用空词典降级，不得覆盖新翻译或清空后的结果。词典请求本身不使用本配置。

## 4. 技术方案（供实施，具体接口命名可调整）

1. **设置层**：在 `DEFAULT_SETTINGS` 增加一个独立的秒数字段（建议 `engineResponseTimeoutSeconds`）；在 `loadSettings()` 合并旧值后规范化，并在设置页输入提交时校验/规范化，不接受 `NaN`、字符串小数、0、负数或超出 1–60 的值。不得让无效存储值直达 timer；保存后重新加载仍得到有效值。新增位置使用现用 `SettingsPage.vue`，UI 保持现有紧凑布局和浅/深色适配。
2. **调度层**：`translate()` 开始时取有效值快照（秒转毫秒），传给 `runEngineFailover()`。对每个 ready 引擎构造一次“调用 Promise + 引擎截止计时器”的受控尝试；解析出主译文后结算成功，截止先到则构造可安全分类的超时错误并走既有 `onFailure`、下一引擎路径。单次结算、`isCurrent()` 和卸载/清空保护要覆盖回调与延迟返回；每次尝试完成时清理计时器。不要只修改 preload 的默认 `TIMEOUT_MS`：那无法限制 uTools AI，也无法约束整个 Google 三源预算。
3. **底层预算传递**：给翻译专用的 `window.services` 调用传递本次预算/截止时间（接口需与现有设置页测试、词典、模型列表兼容）；`requestThirdpartyAI()` 翻译路径需覆盖现有硬编码 30000 ms，其余翻译 HTTP 请求以剩余预算为上限。Google 在进入每个源前核算剩余时间，尽可能取消已超时的库 fetch/Node 请求；避免“总预算已用完仍启动下一个源”及超时后将迟到结果写入缓存。对共享 inflight 的取消要按等待者隔离或引用计数，不可直接取消其他有效消费者。preload 仍使用 CommonJS，所有联网代码仍留 preload。
4. **主译文与词典解耦**：重构 Google/DeepL/DeepLX 的单词路径，使引擎级结算依据主译文而非 `Promise.all([translation, lookupWord])` 或译文后的词典 await；在成功显示主译文后可异步补充词典，补充前检查请求令牌、译文与成功引擎一致。原有 `safeLookupWord()` 的空值/异常降级保留，词典请求的超时策略不受新设置改变。
5. **可观测性及兼容**：沿用 `classifyError()` 的 timeout 安全分类、`recordEngineResult(engine, false)` 和回退提示；524、未配置、桥接缺失等既有行为不变。底层定时器到点时释放可释放的套接字/AbortController；无法取消的 Promise 须挂妥拒绝处理，不对已结算尝试写日志/统计。避免泄露服务端正文和凭据。

4. 按翻译调用链向 preload 传预算，改造 Google 三源剩余时间与安全取消、其他翻译引擎的底层超时；保护缓存/inflight 共享调用；不改变非翻译接口的时限。

## 6. 可验证验收标准

- **AC-001｜默认及设置**：新安装及不含该字段的旧存储均显示 5 秒；1、60 秒可保存并在重进设置后保持；字段为空值、小数、0、负数、61 或非数字时回退并展示 5 秒，合法存储中的其他设置及排序不丢失；整个存储 JSON 损坏时沿用现有加载失败回退默认设置的行为。
- **AC-002｜五引擎超时**：分别模拟五种 ready 引擎永久挂起，设置 1 秒；各自在约 1 秒（允许事件循环/测试时钟误差）内被标记超时，随后**立即**尝试下一引擎；未配置/缺桥接仍跳过且不计失败；每个真实超时只计一次失败。
- **AC-003｜按次预算与快照**：配置 1 秒/5 秒分别触发对应的每引擎截止；第一个超时后，第二个得到独立的完整预算。开始翻译后将设置从 1 秒改为 5 秒，本次全部引擎仍用 1 秒，下次翻译才用 5 秒；不声称整体耗时只等于一个预算。
- **AC-004｜Google 三源**：模拟第一源挂起，其他源待命：Google 总等待不超过自身预算（加合理调度误差），不因三源叠加到 3 倍；第一源提前失败且时间有余则尝试第二源；无剩余时间不再启动新源。相同文本并发等待时，一个超时不破坏另一有效等待者及缓存/去重。
- **AC-005｜超时后显示与反馈**：主引擎超时但后备成功，页面出现后备译文、正确引擎徽标和既有回退提示；所有可用引擎超时/失败时显示安全摘要和重试按钮；日志分类为 `timeout`，失败计入 total/recent，未泄露 URL/请求正文/凭据。524 仍不等待配置时限就回退。
- **AC-006｜迟到及取消**：用延迟 resolve/reject 或永不 settle 的模拟请求验证超时后不回填、不重复统计、不产生未处理 Promise 拒绝；对支持取消的底层请求验证 timeout 时 abort/destroy 且无悬挂 socket/计时器。快速重试、清空和卸载后旧请求均不得覆盖较新结果。
- **AC-007｜词典独立**：单词主译文先于缓慢词典显示并计一次成功，词典随后只补充当前译文；词典挂起/失败不触发回退或改变主译文成功统计；切换输入并启动新翻译、清空或卸载后旧词典结果不得补到新结果。
- **AC-008｜隔离与构建**：AI 语言检测、润色、引擎测试、模型列表及词典自身时限不受新配置改变；`pnpm test`、`pnpm build` 通过。uTools 开发插件及安装形态各手工验证一次超时回退与正常译文；手工验证结论由后续实施者记录。

## 7. 风险与待确认事项

- **实现风险**：uTools AI 可能没有可靠的取消接口；可保证调度超时、忽略晚到结果并消费拒绝，**不承诺物理中止该调用**。若运行时 API 可取消，再使用其公开能力。
- **实现风险**：Google 同 key inflight 去重与按等待者截止时间存在竞争；切勿由一个等待者的取消中断所有人。HTTP helper 到点若只 reject 不 destroy，可能遗留 socket；需在后续实现中复现并校验清理。
- **性能/产品取舍（已确认）**：5 秒是**每引擎**上限而非全链上限；慢而最终可成功的模型可能更频繁回退。Google 第一源如果耗尽预算，其他源无机会尝试；这是共享预算的预期行为。
- **剩余待确认事项：无阻塞项。** 若后续发现 uTools 运行时取消能力、Google 库的 signal 行为与预期不一致，只按上述“尽可能取消 + 可靠忽略晚到”原则调整实现，不擅自改变已确认的用户可见语义。
