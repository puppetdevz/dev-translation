## 2. 数据关卡（GATE-DATA）证据

### 2.1 数据源与版本

权威机器可读版本见 `public/preload/dictionary/SOURCES.json`（原始文件 URL、下载时间、体积、SHA-256）与 `manifest.json`（词库版本、条目数、覆盖统计、来源用途）。

| 用途 | 数据源 | 版本/日期 | 许可 |
| --- | --- | --- | --- |
| 单词美式 IPA | ipa-dict `data/en_US.txt`（基于 cmudict-ipa / CMUdict） | 截至本次下载（见 SOURCES.json） | MIT |
| 选词与排序依据 | `IlyaSemenov/wikipedia-word-frequency` `enwiki-2023-04-13.txt` | 2023-04-13 | MIT |

### 2.2 美式口音依据

- 单词音标唯一来源是 ipa-dict 的 `en_US` 数据文件：数据文件名与项目说明明确其为 English (US)，属于**来源级语义**，不是按 IPA 字符形状推断。其上游为 cmudict-ipa（CMUdict，美式英语发音词典）。
- 词组音标唯一来源是 en.wiktionary 中**带显式地区标注**的读音模板（`a=US`、`a=GA`、`a=GenAm`、`a=General American`，或同一行 `{{a|en|US}}` 等限定）。未标注地区、仅 RP/UK 或其它地区一律不收录，也不从音频文件名推测口音。
- 逐词拼接词组读音被禁止：词组条目只有在整组词条命中且该词条自带美式标注时才写入。
- 在线词典（dictionaryapi.dev）响应不含地区语义，因此其音标一律不采用（`safeLookupWord` 固定丢弃该字段），只可能补充英文释义与例句。

### 2.3 规模与覆盖率

真实统计见 `public/preload/dictionary/COVERAGE.md`（本次生成时同步写入 `manifest.json` 的 `coverage` 字段）：

| 类别 | 条目数 | 美式 IPA | 中文释义 | 英文释义 | 美式 IPA + 中文释义 | 三项齐全 |
| --- | --- | --- | --- | --- | --- | --- |
| 单词（目标 5000） | 5000 | 4957（99.1%） | 5000（100.0%） | 4402（88.0%） | 4957（99.1%） | 4379（87.6%） |
| 固定词组（目标 500） | 500 | 500（100.0%） | 220（44.0%） | 498（99.6%） | 220（44.0%） | 218（43.6%） |

说明：

- 覆盖数量按字段单独统计；**没有任何有效字段的空词条不会被写入词库**，因此不计入条目数。
- 单词按 Wikipedia 词频降序取常用词，并优先收录有中文释义的词条；另加入 `scripts/dictionaryDevTerms.json` 中人工整理的开发常用词词形清单（约 200 项，仅词形、不含词典内容）。
- 固定词组候选池来自 Open English WordNet 的多词词条（词典词条身份）与 en.wiktionary 的可信表达分类（idioms / prepositional phrases / phrasal verbs / proverbs / coordinated pairs / similes）；以各组成词在词频表中的词频之和的对数为常用性代理指标排序，在整池扫描后按常用性顺序取同时具备美式 IPA 与释义的词条。
- 中文释义方向性：中文资料来源是 zh.wiktionary 的英语词条，直接提供中文义项与词性标记；不使用英文释义机翻，也不把「中文译词列表」当作完整中文释义。中英文义项不按数组下标强制对齐。
- 词组美式 IPA 完整率受来源限制（多数常见短语在 Wiktionary 无地区标注读音），未达标项不会被补齐或伪造，仅按字段如实统计。

### 2.4 体积

- 运行数据（`manifest.json` + `shards/*.json`）未压缩实际字节见 `manifest.json`；`scripts/importDictionary.mjs` 在生成结束时输出 MiB 统计。上限要求为 ≤10 MiB。
- 原始大文件（ipa-dict 词表、enwiki 词频表、WordNet JSON 包、Wiktionary 维基文本缓存）保存在 `.dictionary-cache/`（已加入 `.gitignore`），**不进入插件包**。

## 4. AI 命名协议与边界

- 请求内容：本次**原始输入**、语言方向、本次成功主译文；不携带词库义项、历史输入、URL 或凭据。
- 消息结构：`system` 为固定契约（`AI_NAMING_SYSTEM_CONTRACT`），`user` 为用户输入数据；**不复用**翻译提示词或翻译专用 `thirdpartyAiSystemPrompt`，避免翻译指令覆盖命名 JSON 契约。
- 输出：`{"shouldName": true, "words": ["discovery", "count"]}` 或 `{"shouldName": false, "words": []}`；`true` 时词元代表**一个**名称，不是候选列表，也不返回长解释。
- 边界：trim 后 ≤200 Unicode 码点；每轮总预算 10000ms（首次与每次重试各一轮独立预算）；超时/失败/无需命名/无来源/超长各自独立呈现，不影响主翻译、词典补全或翻译统计。
- 隐私：只有用户主动开启后才发送；关闭时不预请求、不默默启用被排除的 AI 来源、不发送历史输入。日志只记录来源、组 ID、类别、阶段等白名单字段。

## 7. 异常模拟方法（非持久化，验收后立即恢复）

在插件页面按 F12 打开开发者工具，在 Console 中执行。所有改写只影响当前会话：**恢复方式统一为 `location.reload()`（或关闭再打开插件）**。若当前宿主不允许在控制台改写 `window.services`（上下文隔离或只读），使用每节末尾的兼容替代步骤，不得为此更换真实凭据。

> 以下片段都只改内存里的桥接函数，不改源码、不改词库、不持久化。

**M1 词典资料延迟超过 5 秒（AC-012/AC-013）**

```js
const realLookup = window.services.lookupWord.bind(window.services)
window.services.lookupWord = (word, timeoutMs) => new Promise(resolve => {
  setTimeout(() => resolve(realLookup(word, timeoutMs)), 8000)  // 比 5 秒预算更晚
})
```
用**不在本地词库中的表外词**触发在线回退（例如虚构词 `zorblat`）。恢复：`location.reload()`。

**M2 只有英式或未标地区的音标（AC-007）**

```js
const realLocal = window.services.lookupLocalDictionary.bind(window.services)
window.services.lookupLocalDictionary = (key) => key === 'parallel'
  ? { found: true, key, kind: 'word', headword: 'parallel',
      phonetic: { value: '/ˈpærəlɛl/', region: 'UK', source: 'synthetic' },
      definitions: { zh: [{ pos: 'adj.', meaning: '平行的', source: 'synthetic' }], en: [] } }
  : realLocal(key)
```
预期：`parallel` 显示中文释义但**不显示音标**（呈现「暂无音标」），不会把英式音标标成美式。

**M3 词典桥接失败（AC-011/AC-012）**

```js
window.services.lookupWord = async () => { throw new Error('synthetic failure') }
```
预期：主译文与常规命名保留，仅出现缺失提示，不切换引擎、不重复计成功。

**M4 AI 命名返回无效结果（AC-024）**

```js
let n = 0
window.services.requestThirdpartyAI = async () => {
  n += 1
  const contents = [
    '{"translation":"hello"}',                     // 错误结构
    '{"shouldName":true,"words":[]}',              // 空 true
    '{"shouldName":true,"words":["发现"]}',        // 中文词元
    '这不是 JSON',                                  // 无效 JSON
    '{"shouldName":true,"words":["discovery","count"]}', // 后续合格来源
  ]
  return { choices: [{ message: { content: contents[Math.min(n - 1, contents.length - 1)] } }] }
}
```
预期：前四种都不产生标签；若顺序中还有后续合格来源，则继续尝试并显示标签；全部无效时显示「AI 命名失败」+ 重试。

**M5 单个 AI 结构结果（AC-024）**

```js
window.services.requestThirdpartyAI = async () => ({
  choices: [{ message: { content: '{"shouldName":false,"words":[]}' } }]
})
```
预期：AI 行显示「无需变量命名」，不回退、不自动重试、不显示标签。

**M6 AI 命名超时（AC-023）**

```js
window.services.requestThirdpartyAI = async () => {
  await new Promise(r => setTimeout(r, 12000))   // 超过 10 秒总预算
  return { choices: [{ message: { content: '{"shouldName":true,"words":["too","late"]}' } }] }
}
```
预期：约 10 秒后 AI 行显示「AI 命名超时」+ 重试；晚到响应不写入标签。用于对照时可同时用 M1 让词典在 5 秒到期：两者互不截断。

**M7 命名调用计数与「只重试命名」（AC-022/AC-023）**

```js
window.__namingCalls = { translate: 0, lookup: 0, naming: 0 }
const svc = window.services
const realTranslate = svc.googleTranslate.bind(svc)
const realLookup = svc.lookupWord.bind(svc)
const realNaming = svc.requestThirdpartyAI.bind(svc)
svc.googleTranslate = (...a) => { window.__namingCalls.translate += 1; return realTranslate(...a) }
svc.lookupWord = (...a) => { window.__namingCalls.lookup += 1; return realLookup(...a) }
svc.requestThirdpartyAI = (...a) => { window.__namingCalls.naming += 1; return realNaming(...a) }
```
翻译一次后查看计数，再点 AI 行的「重试」：预期只有 `naming` 增加。

**M8 陈旧命名/词典回填（AC-013/AC-026）**

```js
let first = true
const real = window.services.requestThirdpartyAI.bind(window.services)
window.services.requestThirdpartyAI = async (url, key, body, timeoutMs) => {
  if (first) { first = false; await new Promise(r => setTimeout(r, 6000)) }
  return real(url, key, body, timeoutMs)
```
