> 记录时间：2026-09-29 15:10（本地时间，CST）
>

## 1. 背景、目标与非目标

当前故障转移顺序需用户拖拽调整，首位就是主引擎。用户虽可对选中引擎逐个点「测试配置」，也可在高级设置中按历史成功率排序，但没有一次测试全部引擎并按**本轮实际可用性和响应速度**自动调整优先级的入口。

**目标**：在设置页一键测试当前五个故障转移引擎，给出逐项结果；本轮至少一个成功时，自动将成功且更快的引擎排在前面，并保存为后续翻译使用的故障转移顺序。

**非目标**：不替换现有单引擎「测试配置」和历史「按稳定性排序」；不修改翻译时的串行故障转移、主译文/词典逻辑或引擎来源；不把本轮测试写入翻译稳定性统计；不跨页面持久化逐项测试结果；不保证一次请求测得的速度等于长期平均性能，也不实现语义准确度评测。

## 3. 已确认的功能需求

- **REQ-001｜入口与覆盖范围**：在当前设置页「翻译引擎配置」的引擎列表旁增加「一键测试并排序」入口。一次点击覆盖五个已知引擎（`ai`、`thirdparty-ai`、`google`、`deepl`、`deeplx`）；未配置或运行环境/桥接缺失者标记为「跳过」且**不发请求**。若旧设置的顺序列表缺项，实施时需保证测试仍覆盖五项，同时避免在无成功时擅自改动原顺序。保留原有拖拽、选中引擎的「测试配置」、高级区「按稳定性排序」。
- **REQ-002｜真实测试与耗时**：每次点击对每个 ready 引擎并行发起**一次**真实翻译请求，五个引擎使用**本轮同一条**带变化标记的短英文测试文本，目标为简体中文；不同轮的文本应变化，避免 Google 相同语言方向/文本的缓存命中。测试在发起调用前后计时；请求在截止前得到非空译文即成功，不要求与标准译文逐字一致。测试会真实消耗服务调用/额度，界面应说明这一点。
- **REQ-003｜截止与分类**：每个实际调用的引擎独立使用本轮开始时从 `engineResponseTimeoutSeconds` 快照取得的截止时间（默认 5 秒，合法范围 1–60 秒）。超时、抛错或空译文记为**本轮失败**；未配置/缺桥接为**本轮跳过**。迟到的 resolve/reject 不得修改本轮已经结算的状态、排序或造成未处理拒绝。不要把设置页原有单引擎测试的超时语义顺带改掉。
- **REQ-004｜排序规则**：等待全部测试结算后计算顺序：成功组按本轮耗时从短到长；失败组在成功组之后；跳过组在最后。失败组、跳过组以及成功组耗时相同者，保持原 `failoverOrder` 中的相对次序；输出不得丢失或重复引擎。**本轮没有成功引擎时原顺序完全不变**，即使存在失败/跳过分组差异。
- **REQ-005｜自动生效与防覆盖**：本轮至少一个成功且测试期间设置未被改动时，测试结束后自动将结果写入 `failoverOrder` 并持久化；首位成为后续翻译主引擎，无需用户再确认。开始时快照顺序、引擎相关配置和超时值；如果期间用户修改配置或顺序、或离开设置页，则此轮结果失效，**不得用旧结果覆盖当前设置**。重复点击时避免启动并发的第二轮，不允许旧轮覆盖新轮。
- **REQ-006｜展示与隔离**：测试期间展示运行状态；本轮结束后在配置区域逐项展示成功及耗时、失败的安全原因或跳过原因，并提示是否完成自动重排。全部失败/跳过时显示「无可用引擎，未调整顺序」及逐项安全原因。单轮结果仅在当前设置页内存中保留，重新进入不显示旧测试结果。批量测试不改已有成功/失败/跳过统计，不把测试原文、URL、Key、令牌或响应正文写进日志/界面错误文案。

## 4. 技术方案（实施建议，不把内部设计选择冒充用户新增需求）

1. **批量测试编排**：在可隔离测试的逻辑模块中实现「检查 ready → 发起一次调用 → 时限内非空判成功 → 汇总 → 排序」；由 `SettingsPage.vue` 管理按钮、生命周期和视图状态。用 `Promise.all`/`allSettled` 等待并行任务**分别结算**；`inspectEngine()` 提供跳过原因，`classifyError()` / `skipUserMessage()` 提供脱敏文案。不要直接复用串行且成功即停的 `runEngineFailover()`，也不要走 `src/Translate/index.vue` 的统计回调。
2. **复用引擎调用**：沿用现有单引擎测试的桥接路径：`window.utools.ai` 与 `window.services.requestThirdpartyAI/googleTranslate/deeplTranslate/deeplxTranslate`。Google / DeepL / DeepLX / 第三方 AI 可传本轮快照时限到 preload 的可选 `timeoutMs`；引擎级结算还须由渲染层统一截止，覆盖 uTools AI、响应解析、底层超时不及时等情况。不新增渲染进程 `fetch()`。测试文本须在同一轮固定、每轮变化且可译（如短英文句附简单变化标记），不展示或记录原文。
3. **耗时及稳定排序**：对每个 ready 引擎从实际发起请求起用单调时钟测量至收到有效译文，毫秒为单位；计时仅用于本轮结果与成功组排序。用原列表位置作为相等耗时的次级排序键，避免运行时排序实现差异；遇旧列表缺少已知引擎时，对额外项可按 `KNOWN_ENGINES` 的既定顺序补在尾部参与测试与成功轮排序，且须保证无成功时不保存任何新顺序。跳过不测耗时；失败耗时可展示为「超时」或失败而非伪装成成功速度。
4. **状态和安全持久化**：开始时持有版本/配置快照，设置变更、拖拽、离页使版本失效；完成后检查版本仍有效，再一次性更新顺序。结合 `useSettings()` 的 `updateSetting()` / `saveSettings()` 行为处理写入失败，避免提示「已保存」但重载后并未生效；实现前需核查现有 `updateSetting()` 不返回保存结果的限制，并选择可测试的反馈方式。运行中禁用重复批量点击；迟到调用只结算一次。单引擎测试与批量测试可保持互不污染的临时结果。
5. **UI**：配置区引擎列表旁增设紧凑入口、逐项状态与完成反馈；适配浅/深色和窄窗口，遵循现有紫色渐变、细边框与高信息密度样式；不让结果区域遮挡配置或导致异常滚动。既有高级统计/手动拖拽功能保持可用。

## 5. 原始实施步骤（15:10 文档阶段未执行）

4. 补充无成功、相同耗时、重复点击、修改设置/拖拽/离页、迟到结果、保存失败和统计不变的回归用例；后续实施时依项目流程检查 `pnpm test`、`pnpm build`，并按第 6 节给出用户可执行的手动验收步骤。**上述命令和验收在原始文档阶段未执行；实施后的隔离测试/构建见第 8 节。**

## 6. 验收责任、操作与标准

**验证责任：uTools 实机验收由用户手动执行；实施时另补充了隔离测试与构建（见第 8 节），不能将其等同于实机验收。** 以下为交付给用户的 uTools 操作及可观察标准。开发形态依 `TESTING.md` 用 `pnpm dev`（端口 5175）并从项目根目录添加开发插件；若要核对已安装形态，另以 `dist/` 加载，不能混为同一次验证。

- **AC-001｜入口及兼容**：打开设置 → 翻译引擎配置，看到一键测试入口及「真实请求可能消耗额度」说明；手动拖拽、选中引擎的「测试配置」、高级区「按稳定性排序」仍能按原方式使用。
- **AC-002｜并行测试及逐项反馈**：配置多个可用引擎并点击一次；五项均进入已结算状态（成功/失败/跳过），没有可调用条件的项不发请求。可用引擎各请求一次，展示成功耗时；整轮不会因为一个引擎挂起而无限等待。运行期间重复点击不会重复开测。
- **AC-003｜超时与失败**：将引擎响应时限设为 1 秒并准备一个会挂起的测试引擎，其他正常引擎仍应有独立的测试结果；挂起项约在 1 秒（允许计时误差）内失败，不阻断其他项。空译文/异常为失败；未配置、桥接缺失为跳过；界面安全展示原因，不泄露凭据、地址或响应正文。
- **AC-004｜排序与生效**：让至少两个引擎成功且耗时可区分，测试结束自动将成功组按耗时升序置前，失败随后、跳过最后，同组并列及失败/跳过内部维持旧相对次序；故障转移列表的 P1 与成功最快者一致。退出重进设置仍保持新顺序；下一次翻译按新首位优先调用。重复执行测试可得到新一轮排序，不使用历史成功率决定本轮名次。
- **AC-005｜全部未成功**：在未配置或不可用的环境下执行一轮，看到每项安全原因及「无可用引擎，未调整顺序」；原排序（包括 P1）不变，重新打开仍不变。
- **AC-006｜防旧结果覆盖**：测试尚在运行时拖拽排序、修改任一引擎相关配置/超时值或离开设置页，待原请求返回或超时；当前配置/顺序均不被旧轮改写。返回设置页不会出现上次的逐项临时结果；新一轮可正常开始。
- **AC-007｜隔离与缓存**：测试前后对比高级区成功/失败/跳过统计，批量测试本身不增加这些计数；单引擎「测试配置」和普通翻译不受影响。连续两轮测试时 Google 不应因完全相同文本命中旧缓存而被错误视为零网络耗时；每轮五个引擎共享同一测试文本。
- **AC-008｜保存失败与隐私**：在模拟存储写入失败的隔离场景，不应虚报已经持久化；若出现可见失败应给出安全反馈。浅色/深色、小窗口中按钮及结果可读，日志或测试提示中无测试文本、Key、令牌和完整服务 URL。

## 7. 风险与待确认事项

- **单次测量波动（已确认取舍）**：一次测速可能受本地网络、服务端抖动、配额、Google 多源回退或不同模型响应影响；本轮最快是观测结果，不保证长期最优。每次真实测试也可能产生第三方计费。
- **缓存与资源（实现风险）**：动态短句降低 Google 缓存命中，但三源、底层连接及服务端缓存仍可能影响可比性；统一引擎截止应保证 UI 结算，但 `utools.ai` 等不一定有可取消接口，迟到响应必须忽略，不能保证远端请求物理取消。
- **竞态与存储（原始实现风险）**：文档编写时 `updateSetting()` 先更新内存后保存且不暴露 `saveSettings()` 结果；实施后已返回保存结果并对存储失败给出安全反馈，未改旧设置迁移逻辑。
- **剩余待确认事项：无阻塞项。** 如果后续真实运行环境暴露新的接口限制或存储失败交互细节，先按上述已确认的用户可见行为实现；不能实现时再向用户确认，不擅自改变排序或验收责任。
