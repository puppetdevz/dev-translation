# 翻译引擎桥接故障：实施记录与验收指引

对应需求：`docs/2026-0929-1354_翻译引擎桥接故障排查与修复.md`  
仓库版本：`package.json` **1.4.1**

## 1. 根因与产物（REQ-001 / AC-001）

日志来自**已安装**插件（路径含 `.asar/assets/…`），不是当前开发插件运行时。

只读核查结论：

| 证据 | 含义 |
| --- | --- |
| `public/preload/services.js` 原在文件顶层 `require('google-translate-api-x')`，随后才赋值 `window.services` | 该 `require` 抛错则整段 preload 中断，桥接整体缺失 |
| `google-translate-api-x` 只在仓库根 `package.json` / `node_modules` | 开发插件可沿目录向上解析到项目依赖，因而开发态可用 |
| 旧 `dist/` 有 `preload/services.js` 但无 `node_modules` | Vite 默认不收集该依赖；打成 `.asar` 后 `require` 失败 |
| 日志中 Google/DeepL/DeepLX「不可用」+ 自定义 AI `requestThirdpartyAI` TypeError | 与 `window.services` 未赋值一致，不能据此判断各服务端是否可用 |
| 524 是 uTools AI 上游错误 | 与 preload 桥接是两条问题 |

修复（加载链路，不在渲染进程伪造 `window.services`）：

1. preload 对 `google-translate-api-x` 改为惰性 `try/catch`，失败只让 Google 库源降级，其它方法仍挂到 `window.services`
2. `pnpm build` 将 `google-translate-api-x` **dereference 复制**为 `dist/preload/node_modules/google-translate-api-x`（真实目录，不是 pnpm symlink）

本次构建核对（实施者本机，不能代替用户安装入口）：

- `dist/plugin.json` → `"preload": "preload/services.js"`
- `dist/preload/services.js` 存在，CommonJS，含 `getGoogleLibrary` / `window.services`
- `dist/preload/package.json` 为 `{ "type": "commonjs" }`
- `dist/preload/node_modules/google-translate-api-x` 为真实目录，从 `dist/preload` 可 `require.resolve` 到该路径

开发服务器单独可用 **不构成** 已安装版通过。

## 2. 隔离用例（不依赖真实外部服务）

```bash
pnpm test
```

覆盖：`window.services` 整体缺失 / 缺单方法、524 只调用一次并回退、未配置不发请求、过期请求不回填、归因不含 TypeError、跳过不污染成功率、旧日志脱敏、preload 在库缺失时仍挂齐方法。

`pnpm build` 通过不等于运行时通过。

## 3. 用户：区分实例并重装

uTools 可能同时存在：

1. **开发插件**：添加时选本仓库根目录，加载 `public/plugin.json` + `http://localhost:5175`
2. **已安装/.asar 插件**：日志里的故障实例；必须用新 `dist/` 覆盖或重装后才生效

仓库无 upx CLI，不要臆造打包命令。请用 uTools 界面：

1. 本仓库执行 `pnpm build`，确认上一节产物都在
2. 打开 uTools → 插件管理 → 开发者
3. **对照已安装形态**：添加开发插件时选择本仓库的 **`dist/`** 目录（不要只选仓库根）
4. 若列表里还有旧的市场安装版，先禁用或卸载，避免继续打开旧 `.asar`
5. 重载插件后打开控制台：preload 不应再有 `Cannot find module 'google-translate-api-x'`；在控制台确认 `window.services` 含 `googleTranslate` / `deeplTranslate` / `deeplxTranslate` / `requestThirdpartyAI` / `fetchThirdpartyModels` / `lookupWord`
6. 需要市场安装包时，在开发者页面对 **`dist/` 这一实例** 使用 uTools 自带「打包」，再安装生成的包。不要把仓库根（含 dev server）打进去

版本识别：设置或 `package.json` 应为 1.4.1；旧 1.4.0/1.3.x 安装包不含本次修复。

## 4. 手动验收清单（用户在真实安装入口完成）

| 编号 | 操作 | 期望 |
| --- | --- | --- |
| AC-001 | 确认当前打开的是新 dist/新包，控制台无 preload 初始化异常，`window.services` 方法齐全 | 开发服务器单独成功不算通过 |
| AC-002 | 临时在控制台 `window.services = undefined` 后翻译、设置页测试、获取模型 | 不抛 TypeError；preload 引擎跳过；uTools AI 可用则仍能出译文并提示回退；日志类别为 `bridge_missing` |
| AC-003 | 恢复桥接，各引擎有配置时分别测试 | 能到达对应 preload 方法；一个失败按原 `failoverOrder` 继续；排序不被改写 |
| AC-004 | 主引擎为 uTools AI，若上游仍 524 | 同一次翻译 AI 只调一次并立刻试下一个已配置引擎。上游未恢复不导致本条失败 |
| AC-005 | 清空或不填 DeepL Key 后翻译 | 不发 DeepL 请求；该引擎「跳过」+1；成功率分母不变；清空统计后跳过数归零 |
| AC-006 | 全部跳过或全部失败 | 摘要可操作（重载/检查版本或去设置填写），有重试按钮，无 TypeError/响应正文 |
| AC-007 | 查看/复制日志 | 无原文、prompt、Key、URL 查询、响应正文；能区分 524 / 桥接缺失 / 未配置 / HTTP 失败 |
| AC-008 | 翻译中途重试、改输入、清空、关插件 | 旧结果不覆盖新结果；单词词典缺失时主译文仍在 |
| AC-009 | 无可用外部引擎时 | 以隔离用例验证回退与桥接，以真实环境验证 preload 加载；不宣称 Google/DeepL 已恢复 |

词典降级策略：`lookupWord` 缺失或失败返回空音标/释义/例句，不影响已成功主译文。

设置页「测试配置」失败不写入翻译引擎统计。
