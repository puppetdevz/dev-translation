# 新增百度、阿里、彩云翻译引擎：需求与实施方案

> 状态：需求已实现（代码接入、隔离测试与构建已完成）；三家真实 API 连通性、计费及 uTools 交互仍须用户按第 6 节手动验收，不得将 mock 结果视为实测。初次记录时间：2026-09-29 21:34（本地时间）。

## 1. 背景与目标

目前产品只有 uTools AI、自定义 AI、Google、DeepL 官方和 DeepLX 五个顶级引擎。新增三个可独立配置的**官方文本翻译 API** 引擎：百度翻译通用文本翻译**标准版**、阿里云机器翻译通用版 `TranslateGeneral`、彩云小译文本翻译 API。它们须参与现有中英双向翻译、串行故障转移、设置排序、单引擎测试、一键测试及自动排序、日志统计和结果来源展示。

**非目标**：不扩展语种选择（仍仅中译英、英译中）；不接入非官方网页或第三方网关；不扩展润色能力（保持现有 AI 路径）；不新增分段翻译、重试或跨引擎共享代理；不承诺凭据的加密存储，也不改造现有存储体系。彩云网页/App 的字数限制不得冒充其 API 的限制。

## 2. 现状及涉及模块

- `public/preload/services.js`：CommonJS/Node 侧承接所有联网引擎，向渲染侧暴露 `window.services.*`；Google 专用代理只允许 Google 使用。新增三家的真实 HTTP 请求、官方鉴权、超时和响应解析均放在 preload，组件不得直接 `fetch`。
- `src/Translate/utils/storage.js`：`dev-translation-settings` 单键持久化；`DEFAULT_SETTINGS` 默认顺序为 5 引擎，`KNOWN_ENGINES` 控制加载时白名单过滤；`loadSettings` 还含旧主引擎、第三方 AI、DeepL/DeepLX 等迁移逻辑，改动必须保留原行为。`src/Translate/utils/useSettings.js` 提供共享设置单例。
- `src/Translate/utils/engineBridge.js`：显示名、preload 方法、可用性检查、跳过/失败分类及每个已调用引擎的一级超时（默认 5 秒，1–60 秒）；跳过不计成功率；`DICT_ENGINES` 决定主译文成功后是否做非阻塞词典补充。
- `src/Translate/index.vue`：按 `failoverOrder` 串行翻译，首位为主引擎；当前语言方向归一为 `en ↔ zh-CN`；成功后标注实际引擎。`src/Translate/components/SettingsPage.vue`：现行设置页，负责配置、排序、单项测试和批量测试；勿改无引用的旧设置组件。
- `src/Translate/utils/engineProbe.js`：一键测试遍历已知引擎，用配置快照和实际耗时决定是否自动重排；`src/Translate/utils/engineStats.js` 与 `src/Translate/utils/safeLog.js`：统计及日志白名单脱敏。测试参考 `scripts/engine-bridge.test.mjs`、`scripts/engine-probe.test.mjs`、preload 相关隔离测试和 `TESTING.md`。

## 3. 功能需求

- **REQ-001 官方接入**：分别新增 `baidu`、`aliyun`、`caiyun` 三个顶级标识。百度用 APPID + 密钥，阿里用 AccessKey ID + AccessKey Secret（有 `alimt:TranslateGeneral` 权限且已开通服务），彩云用**开放平台申请的 API Token**（普通会员账号不等于 Token）；只对官方 HTTPS 域名发请求。参数与响应按各官方文档适配，不以 HTTP 200 代替业务成功。
- **REQ-002 配置与安全**：设置页在「引擎」分类为每家提供独立凭据字段、官方凭据申请入口、缺项/保存失败提示、凭据遮罩；沿用现有 uTools `dbStorage` 保存，不宣称加密。禁止将凭据、原文、原始请求/响应体、请求 URL 写入日志、错误提示、统计或构建产物；不使用 Google 专用代理。仅用户本机配置，代码/文档不写测试凭据。
- **REQ-003 翻译行为**：沿用现有语言判定和 `en ↔ zh-CN` 双向翻译；preload 为不同厂商映射语言代码（例如将简中规范化为 `zh`，彩云方向使用 `en2zh`/`zh2en`）；返回非空 `{ translation }` 主译文。英文单词的词典补充沿用现有 `lookupWord`，失败不推翻主译文、不占一级时限；句子等沿用当前不查词规则。润色保持现状。
- **REQ-004 顺序与升级**：新装默认顺序为旧五引擎原顺序后依次追加百度→阿里→彩云；升级加载时保留原主引擎、旧相对顺序和已有自定义排序，缺失的新引擎仅在末尾按该顺序补入，每个标识最多一次；重复加载保持幂等。白名单、旧配置迁移和过滤空列表回退继续有效。用户可手动拖拽设为主引擎。
- **REQ-005 可用性与回退**：缺 preload 方法/桥接按环境缺失跳过；缺任一必填凭据按配置缺失跳过；两者不发请求、不计成功率。已发起请求的鉴权、额度/欠费、限流、业务错误、空译文、网络错误、超时等计本引擎一次失败并转下一引擎；524 按现有机制立即回退，超时沿用 `engineResponseTimeoutSeconds`。不在单引擎内暗中重试，避免重复扣费。晚到响应不得覆盖新请求或重复统计。
- **REQ-006 本地超长预检**：百度标准版按官方单次 **1000 字符**、阿里 `TranslateGeneral` 按 **5000 字符**做请求前预检（按官方字符口径，包含空格/标点；实施时以最新版官方口径复核）。超过限制不发该引擎请求，作为**输入限制跳过**计数而非失败，提示安全的「文本超过该引擎单次限制」并转下一引擎；不分段。彩云 API 文档未明确单次上限，**不得自行编造阈值**，如官方接口返回超限则按已发请求失败回退；官方正式确认上限后再决定是否补预检。
- **REQ-007 测试与观测**：三引擎进入设置页单项真实测试（固定安全测试文本）、一键测试/自动排序、结果来源、成功/失败/跳过统计及安全日志；未配置/超长的跳过不参与成功率及耗时排序成功组。批量测试使用配置快照；测试期间修改新凭据或顺序时不应用旧测试结果。用户可查看真实请求失败与跳过的安全类别，但不得显示厂商返回的未经净化原文。
- **REQ-008 兼容与界面**：保持已有 5 引擎、词典、其他设置和旧统计数据可用；现行设置页新增项遵循现有紧凑布局、深色模式、窄屏与已约定的样式。新增功能不要求增加独立路由或 `plugin.json` feature。

## 4. 技术方案（供实施）

1. 在 preload 封装三家官方调用，接受原文、源/目标语、对应凭据和超时。百度按官方签名规则以 Node `crypto` 计算 `MD5(appid + q + salt + 密钥)`，签名前使用原文，发送时再对参数编码；解析 `trans_result` 与 `error_code`。阿里调用 **OpenAPI `TranslateGeneral`**（`FormatType=text`、`SourceLanguage`、`TargetLanguage`、`SourceText`、`Scene=general`），按官方鉴权规范选择适用于现有 CommonJS preload 的官方 SDK 或等价签名请求实现；优先官方 SDK，但必须验证依赖可离线打包、HTTPS、可控超时和错误分类，**不得照搬旧 HTTP REST 示例**。响应以业务 `Code` 和 `Data.Translated` 验证。彩云 `POST /v1/translator`，Header `X-Authorization: token <Token>`，请求 `source`、`trans_type`、`detect` 等按官方规范组装，提取有效 `target` 并检查业务错误。
2. 统一厂商响应到非空译文或**仅含安全类别/状态码**的异常；签名、Token、鉴权头、原文均不可进入异常字符串。请求按超时取消底层连接（可行时）并避免迟到响应继续落 UI；不用 Google 代理。若引入依赖，应核对 `pnpm` 安装、preload CommonJS 加载与 `dist/preload` 的真实文件打包，不能只保证 dev 生效。
3. 在 `storage.js` 增加默认空凭据和三个已知标识，采用缺项末尾补全、去重、幂等迁移；保持已有兼容逻辑。`engineBridge.js` 扩展方法/名称/必填配置检查、`DICT_ENGINES` 和**输入限制跳过**分支；输入跳过应具有独立可识别的原因/统计归类，不伪装成「未配置」，且需要与 `safeLog.js` 白名单同步。对 `runEngineFailover` 与 `engineProbe.js` 的预检保持一致，确保预检发生在真实调用及失败结算之前。
4. `index.vue` 添加三个服务调度分支，统一经现有 `runMainTextTranslation` 与词典补充机制；`SettingsPage.vue` 增加配置、单项测试分支与 UI 元数据；`engineProbe.js` 增加配置快照比较和三个调用分支。新旧引擎都沿用现有一级时限和故障转移语义，自定义 AI 组链的独立二级时限不得回归。
5. 实施时为签名/语种映射/厂商业务错误及空结果、缺配置/超长跳过、升级幂等与去重、探针快照与重排、隐私脱敏、超时与回退编写隔离用例，避免真实外部请求；推荐纳入项目现有 `pnpm test`/`pnpm build` 流程，但**本需求的最终验收责任按第 6 节由用户手动承担**。

官方接口参考（实施时复核版本与计费）：[百度通用翻译文档](https://fanyi-api.baidu.com/doc/13)、[阿里 TranslateGeneral](https://help.aliyun.com/zh/machine-translation/developer-reference/api-alimt-2018-10-12-translategeneral)、[彩云小译 API](https://docs.caiyunapp.com/lingocloud-api/index.html)。这些链接是实现依据，不代表已持有或验证用户的服务凭据。

## 5. 建议实施步骤

1. 对照官方资料核对三家当前签名、语言代码、账户权限、字数限制、响应/错误格式和阿里 SDK 打包方式；先建立脱敏 mock 和回归用例。
2. 完成 preload 的厂商适配与离线可打包验证，再更新默认设置、迁移和引擎桥接的跳过/失败判定。
3. 接入翻译页及词典补充、设置页凭据/单项测试、一键测试与快照排序、统计与安全日志；检查所有旧引擎回归。
4. 向用户交付本地开发插件（项目根目录 + 5175）与已安装版（`dist/`）的手动验证步骤，提示两者并非同一实例；按下述标准由用户验收。

## 6. 验收操作与标准

**验证责任：用户将手动验证，Harness 无需执行自动化验证，完成实施并给出手动验证步骤即可。** 用户已确认可准备三家有效 API 凭据和开通/有额度的账户；以下真实调用须由用户在 uTools 中自行操作。Harness 不得将仅 mock 通过写成「三家真实 API 已验证」。用户手动检查时可参照 `TESTING.md` 开发插件/安装包两种独立实例的安装路径。

- **AC-001 配置与升级**：使用已有五引擎自定义顺序的旧设置启动升级实例；在设置页确认旧首位与相对顺序不变，末尾只出现百度、阿里、彩云各一次；重启后不再重复追加。新实例默认五引擎在前、三引擎按百度→阿里→彩云在后。缺凭据时显示未配置，不能发出该引擎请求。
- **AC-002 三家真实双向翻译**：在设置页分别填三家真实凭据，逐个点单项测试确认成功；分别将三家拖到首位，各翻译一次英文短句→简中、中文短句→英文，译文非空且结果来源正确；英文单词模式可补词典，词典失败时主译文保留。润色仍走原路径。
- **AC-003 顺序与故障回退**：使某家缺凭据，确认该引擎跳过且下一已配置引擎成功；改用失效凭据或无额度账户模拟已发请求失败，确认该引擎恰记一次失败、下一引擎接管且 UI 有来源/回退提示；用可控慢响应或网络故障核对一级超时回退及旧请求不会覆盖新结果。
- **AC-004 长度边界**：输入百度标准版超过 1000 字符、阿里超过 5000 字符分别验证对应引擎**本地跳过、零次请求、下一引擎继续、不增加该引擎失败/成功率分母**；边界内文本能发送。彩云不做臆定数值的本地截断，若 API 返回超限，则失败回退。手动测试超长时注意可能的其他引擎调用费用。
- **AC-005 批量测试与观测**：在三家配置有效时运行一键测试，八引擎各有独立结果，成功按耗时排序且可设置新主引擎；未配置者显示跳过，不算失败；测试过程中修改新增凭据或排序，不应用过期结果。检查三家成功/失败/跳过统计和日志仅含安全元数据，无凭据、原文、URL、原始响应。
- **AC-006 构建与既有功能**：在项目根目录加载开发插件后，再用独立安装形态 `dist/` 验证三家桥接方法可用；原五引擎翻译、词典、设置、超时、拖拽排序和暗色/小窗界面无回归。用户按实施者给出的步骤记录通过/失败项。

## 7. 风险与待确认事项

- **实现前须核实的外部事实**：百度标准版 1000 字符与阿里 5000 字符限制、官方计数口径、QPS、阿里最新鉴权和可用的 CommonJS/构建方案；如官方规定变化，以官方文档为准并先向用户确认是否调整本需求，不擅自将变化写成原有确认。
- 彩云公开 API 文档未标出明确的单次文本上限/完整错误码；**这是外部待核实项，不是已确认数值**。当前已确认决策为不自设阈值、接口报超限后按已请求失败回退；如将来获得官方限制，可另提变更。
- 用户已接受本地 `dbStorage` 存储敏感凭据的既有模式；这不是加密或防本机读权限的安全保证。翻译请求和批量探针可能消耗付费额度，真实鉴权/欠费场景也依赖账户状态与网络。
- **剩余用户决策：无。** 以上外部核实与 uTools 真实连通性属于后续实施/用户手动验收事项，不应被冒充为本次已实测结论。
