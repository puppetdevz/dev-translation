# 设置界面布局重构：需求与实施方案

> 状态：需求已澄清；**仅为后续实施文档，本次不修改代码、不执行功能验收**。记录时间：2026-09-29 16:25（本地时间）。

## 1. 背景、目标与非目标

当前设置页以纵向长页面呈现语言检测、翻译引擎配置及折叠的高级设置；引擎区域已经包含五引擎排序、配置、批量测试、自定义 AI 组和输出开关，随着设置项增多，整体查找与排布需要重构。

**目标**：将整个设置页改为分类导航，在宽窗口用侧栏、窄窗口用顶部标签；缩短寻找设置项的路径，保持高信息密度且允许复杂区域滚动，兼顾窄/矮窗口、浅色/深色模式以及键盘操作。引擎配置内部继续采用双列布局，在空间不足时合理堆叠。

**非目标**：不新增配置字段、设置搜索或业务功能；不更改翻译、故障转移、超时、排序、测试、日志、统计与持久化的业务规则；不改插件入口、路由语义或 preload 网络服务；不要求所有复杂配置与日志在一屏内完全展示。

## 3. 功能需求

- **REQ-001｜分类架构**：设置页分为“常规 / 引擎 / 高级”三类。常规包含语言检测策略、输出设置；引擎包含响应超时、一键测试并排序、五引擎排序及选中引擎配置（含自定义 AI 组）；高级直接显示稳定性统计与日志管理，移除“进入高级后还要点一次”的总折叠层。所有现有设置项、提示、操作和反馈仍可找到。
- **REQ-002｜导航与初始状态**：宽窗口显示侧栏分类导航及右侧当前分类内容；宽度不足时切换为内容上方的分类标签。设置页每次新进入默认“常规”；在同一次进入中切换分类不会重置用户已编辑的配置、选中引擎或临时操作状态。切换不应导致整页/导航滚动丢失；固定导航，当前分类的内容区可纵向滚动。
- **REQ-003｜引擎区布局**：在侧栏以外，引擎内容区仍采用引擎列表＋选中引擎配置双列；内容宽度不足时堆叠，保留五项顺序、P1 标识、选中态、拖拽重排、单引擎测试、批量测试、组管理及结果/错误反馈的可见性与可操作性。不得将“分类侧栏”与“五引擎排序列表”混为同一个组件或排序对象；跨窗口尺寸变换后仍可确认各引擎的优先级。
- **REQ-004｜输出设置语义**：输出开关移至“常规”；仍根据**主引擎**决定可展示的选项和说明。引擎分类更改主引擎顺序后，切回常规立即反映当前主引擎的输出选项；设置的实际保存及作用不变。
- **REQ-005｜高级内容**：“高级”分类进入后直接展示统计与日志；保留刷新、按稳定性排序、清空统计、日志等级/保留时间、最近错误、复制/清空日志等现有操作及其反馈。移除原折叠控制时保证首次进入以及从其他分类再次进入可查看最新数据，不因隐藏分类或折叠高度限制截断内容。
- **REQ-006｜异步与切换边界**：仅在“常规 / 引擎 / 高级”分类间切换时，进行中的批量测试、单引擎/组测试、模型获取、输入框内容和结果状态仍保留，返回分类可以查看；**真正离开 `/settings`** 时维持现有离页失效/防旧请求覆盖机制。不得因分类切换让旧测试结果改写新配置或造成未处理异常。
- **REQ-007｜视觉、响应式与可访问性**：采用项目既有紫色强调、细边框、轻阴影和深色模式约定，布局紧凑但文字与控件可辨、操作可点击。常规窗口、宽度 ≤640px 的窄窗口及高度 <600px 的矮窗口均可访问全部分类及其设置；避免横向溢出、遮挡、文字/提示被裁剪。分类可通过 Tab 聚焦并用 Enter/Space 切换，有清晰焦点样式、可辨别的选中状态及合适的语义标签。
- **REQ-008｜保持既有行为**：设置读写与旧配置兼容不变；拖拽后首位仍是主引擎；批量测试与按稳定性排序各自保持原规则；高级统计与日志的计数、脱敏及安全提示不因布局更改；返回翻译页及再次进入设置页仍按原路由工作。

## 4. 技术方案（供后续 Harness 实施）

1. 在实际设置页组件中划分三块语义清晰的分类内容，以组件局部状态记录当前分类，初值“常规”，不持久化分类选择；沿用原路由和共享设置单例。分类导航使用真正的按钮及可感知当前选中项的状态，按键/焦点样式明确。实现可采用 tablist/tab/tabpanel 或等效可访问语义，但所选语义与键盘行为须一致。
2. 将原 `settings-body` 的长页布局调整为“固定顶部栏＋导航＋当前内容可滚动”的区域约束；使用 CSS Grid/Flex 的合理 `min-width: 0`、`min-height: 0` 和溢出边界，避免窄屏、矮屏、长 URL/模型名与日志撑开页面。宽屏侧栏与引擎区自身双列是**两层不同布局**；空间不足时顶部标签＋引擎区堆叠。断点是实现细节，可在现有 640px/768px 媒体规则基础上调整，但必须满足 REQ-007 的覆盖范围及实际可用性。
3. 将“输出设置”原模板/样式迁移到常规分类，保留 `mainEngine` 依赖和开关绑定；将高级折叠外壳改为直接内容，不再依赖 `advancedOpen`/`toggleAdvanced` 才能展示数据；分类进入或可见时核查原刷新行为，防止旧折叠点击曾触发的统计刷新被遗漏。
4. 用保留挂载状态的展示策略（例如 `v-show` 或等价方式）维护分类内组件的输入与异步结果，不因切分类触发页面级离开逻辑；保留路由离开时已有的失效保护。注意高级统计/日志的可见刷新与隐藏期间异步反馈，以及返回分类后的滚动位置/焦点可用性。
5. 复用并整理现有浅/深色、响应式样式；删去失效的折叠样式，核对动效仅使用 transform/opacity 的项目约定；复查自定义 AI 组卡片、超时字段、批量探测结果、稳定性统计行及日志列表在窄/矮窗口的换行和滚动，不以裁剪来“实现紧凑”。

## 5. 实施步骤

1. 对照现有设置页模板/样式和 `TESTING.md` 列出三类各控件及反馈的位置清单，记录现有测试/组请求的生命周期和当前主引擎驱动输出选项的依赖。
2. 先实现分类导航、初始常规页、语义化键盘切换和宽/窄布局骨架；确保顶部返回及 `/settings` 路由未变。
3. 迁移常规、引擎、高级内容，保留原事件绑定和持久化；移除高级总折叠层并补足需要的刷新时机。
4. 处理引擎区内部双列→堆叠、自定义 AI 组、测试反馈、高级统计/日志在窄/矮窗口的可用性及深色模式；核对分类切换时异步状态仍保留，离页保护仍有效。
5. 后续实施时自查变更范围、回归 `pnpm test` / `pnpm build`（仅作为实施者开发自查建议，**不是用户要求 Harness 执行的验收义务**）；交付可供用户逐项手动验收的步骤，并说明未在 uTools 中验证的项目。**本次仅写文档，未执行这些命令。**

## 6. 验收操作与验收标准

**验证责任：用户将手动验证，Harness 无需执行自动化验证，完成实施并给出手动验证步骤即可。** 下列操作供用户在后续代码实施完成后手动执行；本次文档工作不代表功能已通过验收。可按 `TESTING.md` 启动 `pnpm dev`（5175），在 uTools「插件管理 → 开发者 → 添加开发插件」选**项目根目录**打开插件；若另验安装版，构建后改选 **`dist/`**，不得混用两种实例。

- **AC-001｜分类与入口**：从翻译页点设置，默认选中“常规”；可切“引擎”“高级”，再次离开设置页并重新进入仍默认“常规”；顶部返回可回翻译页。三个分类各自有明确选中态，无设置项丢失。
- **AC-002｜常规及输出**：常规下切换正则/AI 检测策略和输出开关，退出重进后值仍正确；到引擎页拖动改变 P1，再回常规，输出选项按**新的主引擎**展示，而非按引擎页选中的配置卡；翻译页相应行为与设置保持一致。
- **AC-003｜引擎配置**：引擎分类可见超时、一键测试并排序、五引擎顺序与详情；拖拽改变 P1 并重进仍保存；切换五引擎可定位对应配置和“测试配置”，自定义 AI 组新增/编辑/重排/删除及模型获取的入口、保存/错误提示可用。执行真实请求前确认测试额度与环境；未配置服务可重点验证跳过/安全错误反馈，不要求为了布局验收采购服务。
- **AC-004｜高级**：点击“高级”即直接看到统计和日志，无第二次展开；记录变动后切离再切回/点击刷新，数据可读且操作可用；“按稳定性排序”、清空统计、日志等级/保留时间、最近错误、复制/清空日志未因重排失效；显示与复制的日志不泄露原文/凭据。
- **AC-005｜切换与离页**：在可控测试条件下于引擎批量测试或模型获取期间切到常规/高级，再切回引擎，运行状态与结果不丢失且不错误写入旧排序；有自定义 AI 组/字段输入时切类再返回内容保持。真正返回翻译页、随后重进设置时，旧的异步结果不得覆盖新设置（如缺少测试服务，记录未覆盖项而非声称通过）。
- **AC-006｜窗口与主题**：分别在常规宽度、≤640px 窄宽度、<600px 高度检查三个分类，并切换浅色/深色：宽时侧栏、窄时顶部标签；窄时引擎列表和配置堆叠；导航可用、内容可滚动、无页面级横向溢出或控件/错误提示被遮挡，长模型名与日志仍可辨或可滚动查看。
- **AC-007｜键盘可用性**：仅用 Tab 聚焦三类导航，用 Enter/Space 激活并切换到正确内容；当前项和键盘焦点在两种主题与窄/宽布局下可识别，键盘可到达返回按钮与主要表单控件。

## 7. 风险与待确认事项

- **风险：布局层级挤压**。侧栏与引擎区双列叠加可能使中等宽度内容过窄；后续实施须按可用宽度调整断点，兼顾 640～768px 等过渡区间，避免只有 ≤640px 适配。
- **风险：隐藏分类与异步生命周期**。不应因条件卸载触发等同离开设置页的清理；反之真正离页时不能让旧结果回写。高级折叠去除后，原刷新入口/高度限制不能遗留导致统计或日志不更新、不可见。
- **风险：真实测试的网络/额度**。涉及单引擎、批量测试与模型获取的手动验收可能产生真实请求；无可控测试服务时应记录未覆盖项，不能将跳过、错误或未执行冒充成功。
- **待确认事项：无阻塞项**。分类范围、归属、默认页、宽/窄导航、滚动方式、切分类状态、视觉密度、键盘支持及手动验收责任均已由用户确认。具体侧栏宽度与切换断点属于实施细节，以无溢出、可操作的验收结果为准；若后续希望额外新增搜索或改变测试业务规则，须另行确认，不得视为本需求已包含。
