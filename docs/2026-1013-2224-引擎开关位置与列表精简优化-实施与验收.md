## 2. 实现说明（需求 → 代码）

### 2.1 列表精简（REQ-001、REQ-002）

- 删除 `.engine-card` 内的 `toggle-switch engine-enable-toggle` 与 `.engine-kind-tag` 节点；本组件删除 `engineKindLabel` 导入，共享分类 API（`engineKind()` / `engineKindLabel()`）保留不动。
- 卡片保留：`.engine-drag-handle`、图标 / `.brand-badge`、`.engine-card-name`、`.engine-card-meta`（`主引擎` / `已关闭` / `未配置`，条件不变）、`.engine-priority`（`P{{ index + 1 }}`）。卡片仍是 `draggable="true"`，点击仍调用 `selectEngine(engine)`，关闭项仍可选中编辑。
- 清理 `onDragStart` 中只针对列表开关的死分支（`closest('.engine-enable-toggle')` + `preventDefault()`），保留 `dragIndex.value = index` 与全部拖拽/落点逻辑；右侧开关不属于可拖拽卡片，无需该保护。
- 删除本组件中 `.engine-kind-tag` 的浅色/深色样式；`.engine-card-title` 仅保留名称并新增 `max-width: 100%`，使长名称在卡片内省略而不是溢出遮挡（见 2.4）。

### 2.2 详情标题栏唯一开关（REQ-003、REQ-004、REQ-005）

- 共享头部 `.engine-config-header` 内新增操作容器 `.engine-config-actions`，顺序为 `.engine-enable-control`（固定可见标签「启用引擎」+ 滑动开关）→ `.engine-test-btn`，八类引擎共用同一份模板。
- 绑定：`:class="{ active: selectedEngineEnabled }"`、`:aria-pressed`、`:title`（沿用开启/关闭说明）、`:aria-labelledby="engine-config-name-${selectedEngine} engine-enable-label-${selectedEngine}"`、`type="button"`、`draggable="false"`、`@click="toggleEngineEnabled(selectedEngine)"`。
- 状态来源是既有计算值 `selectedEngineEnabled = computed(() => isEngineEnabled(settings, selectedEngine))`，点击调用既有 `toggleEngineEnabled(engine)` → `setEngineEnabled(...)` → `persistSetting('engineEnabled', next)` → `updateSetting(...)` → `saveSettings(...)`。不新建本地 ref、不新增 watch 复制状态、不新增设置字段。
- 「启用引擎」是固定文案的 `<span>`，通过 `aria-labelledby` 与开关建立可访问名称；没有做成第二个可点击的启停按钮，`<label for>` 未使用以避免出现重复点击目标。
- 现有 `.engine-config-warning.engine-disabled-warning`（该引擎已关闭提示）、未配置提示、测试 loading / 结果展示与测试互斥规则均未改动。

### 2.3 无请求、无统计、无弹窗（REQ-006、REQ-007）

本次只改模板结构、样式与死分支，未触碰 `persistSetting`/`saveSettings`、`engineProbe.js` 快照、`engineStats.js`、`safeLog.js`；切换开关仍只写 `engineEnabled` 映射，不触发测试、不新增网络请求、不新增统计、不弹确认框，不改 `failoverOrder`。`toggleEngineEnabled` 的函数体未变。

### 2.4 样式与响应式（REQ-008、REQ-009）

- `.engine-config-header` 改为 `display:flex; flex-wrap:wrap; gap:8px 12px`；`.engine-config-heading` 用 `flex:1 1 160px; min-width:0`，`.engine-config-actions` 用 `flex:0 0 auto`。操作区是单个 flex 项且内部 `.engine-enable-control` 为 `flex-wrap:nowrap`，因此空间不足时「标签 + 开关 + 测试按钮」整体换到第二行，标签与开关不会被拆开，开关始终在「测试配置」左侧；换行不依赖 ≤640px 媒体查询。
- 开关沿用 38×22px 紧凑规格（`.toggle-switch.engine-enable-toggle`），保留 `.toggle-switch:focus-visible` 焦点描边；新增 `.engine-enable-label`（浅色 `var(--text-secondary, #64748b)`，深色块内覆盖为 `#94a3b8`）；删除的类型标签样式不再有深色遗漏。
- **附带窄窗修复（超出需求文档的严格清单，但为满足 AC-009「无遮挡、横向溢出」）**：原 ≤640px 列表规则 `.engine-card { flex: 1 }`（basis 0）会把八张卡片挤进同一行，卡片内容（尤其名称）溢出并被 `.settings-panel` 的 `overflow-x: hidden` 裁切（实测 640px 下横向溢出 21～33px，520px 下 36～48px）。改为 `flex: 1 1 132px`（真正换行），并给 `.engine-card-title` 加 `max-width: 100%`（名称省略）后，所有量测宽度下溢出归零。该改动仅影响 ≤640px 的卡片宽度分配与名称省略，不改变列表在上、详情在下的结构，也不恢复任何行内启停入口。

### 5.1 保存失败的手动构造与恢复（需求文档 6.3，用户执行）

仅在用户可控的开发测试实例中执行，不修改源码、不打印设置载荷：

1. 宿主开发者工具中私下保留 `window.utools.dbStorage.setItem` 原方法及其所属对象。
2. 临时包装：键等于 `dev-translation-settings` 时返回 `false`，其余键用原对象作为 `this` 透传原方法；不要输出参数（第二参含凭据）。
3. 用真实界面点击右侧开关，核对 AC-010；再把该键分支改为抛出固定无敏感内容的 `Error`，重复核对。
4. 还原原方法；按需要点击开关回到期望状态，确保实际执行一次正常保存，再重载核对。
5. 恢复验收前的顺序、开关与配置。重载可清除内存替身，但不能撤销已经持久化的设置。

宿主方法不可写时不得声称异常已验证，应按需求文档 6.3 请求可用的替代替身环境。
