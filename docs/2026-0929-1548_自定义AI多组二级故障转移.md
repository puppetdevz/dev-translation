## 1. 背景、目标与非目标

当前「自定义 AI」只有一套 API 链接、API Key、模型配置，在五个一级引擎的 `failoverOrder` 中只占一个位置。该服务失败时只能直接切换其他一级引擎，无法优先尝试同类服务的备用配置。当前系统提示词虽然是一个独立字段，但界面未明确表达其在多组场景下的共用关系。

**目标**：在「自定义 AI」一级引擎下配置多个可命名、可排序的组；轮到该一级引擎时，按组顺序逐一尝试，首组成功即停止，所有组未成功才切到下一个一级引擎。提供与一级超时相互独立的二级超时；现有单套配置无损迁移为首组；界面明确展示一份对所有自定义 AI 组**通用**的系统提示词。

**非目标**：不把每组变成新的一级引擎标识；不调整 Google、DeepL、DeepLX 或 uTools AI 的翻译逻辑；不使共享系统提示词作用于 uTools AI、润色或配置测试；不按组维护长期成功率/历史稳定性排序；不在组件中新发渲染进程网络请求；不要求改变原有一级引擎的自动排序算法或一级引擎时限。

## 3. 已确认功能需求

- **REQ-001｜层级与顺序**：保留五个一级引擎标识及 `failoverOrder`；「自定义 AI」只占一个一级位置。轮到它时，按可手动调整的二级组顺序串行尝试，第一组成功立即返回；该组链全部未成功后才继续尝试下一个一级引擎。一级拖拽、按稳定性排序及主引擎首位语义保持不变。
- **REQ-002｜组配置与管理**：每组独立保存稳定 ID、唯一显示名、API 链接、API Key、模型；支持新增、重命名、删除（需确认，删除时从持久化配置移除该组及 Key）、手动调整优先级。空名自动生成不重名名称，重名不可保存；允许删到零组，零组时该一级引擎跳过。首次使用默认展示一个空组。组顺序及编辑结果跨重启保留，不能以可变名称作调用标识。
- **REQ-003｜模型选择及独立 UI 状态**：各组均可手填模型，也可使用该组 URL/Key 调用现有模型列表桥接并选择；加载状态、列表、错误、当前选中模型分别归属于对应组。组删除、更改凭据或切换时，旧异步结果不得写入其他组或覆盖新配置。
- **REQ-004｜二级故障转移分类**：组的 URL、Key、模型任一缺失时该组为 `skipped`，不发请求、不记真实失败，继续下一组；桥接缺失或方法不可用亦按环境跳过。已经发起调用后 524、HTTP 错误、解析失败、空结果、异常或超时都属于本组真实失败，并尝试下一组；最后一组失败/跳过后才转下一个一级引擎。各组应调用现有相同的 OpenAI 兼容请求及译文解析路径，不能仅凭非空但不可用的译文对象误报成功。
- **REQ-005｜二级超时独立**：设置页提供**一处二级超时**，所有组按此相同上限**各自单独计时**；默认 5 秒，允许 1–60 的整数秒，无效/缺失值恢复 5 秒。与一级超时设置相互独立：一级时限继续约束其他一级引擎，但**不**作为自定义 AI 整条组链或单组的额外截止条件。超时的组只结算一次且立刻尝试下一组；迟到结果不得覆盖成功译文或重复计数。正式翻译、每组直测、自定义 AI 的一级测试及一键批量测试中的自定义组链均遵守二级逐组时限；其余引擎的测试时限按现有规则。
- **REQ-006｜旧设置兼容**：首次读取无新组字段的旧设置时，将原有 `thirdpartyAiUrl/Key/Model` 迁为第一组（即使尚未填满也不丢失已填内容），`thirdpartyAiSystemPrompt` 保留为全组共用提示词；保留现有一级顺序及一级超时。首次空设置展示一个空组；**明确持久化的零组不可被下次加载自动补回**。重复加载/保存不得重复迁移、重复组 ID、抹除 Key 或重新排列。后续保存可清理不再使用的旧三字段，避免配置双来源。
- **REQ-007｜通用系统提示词**：在组配置区域独立展示一份可编辑的「通用系统提示词（适用于所有自定义 AI 组）」并说明它与现有默认 `user` 翻译指令的关系；所有组正式翻译均发送同一份已配置 `system` 消息，留空时与现有逻辑一致、不追加 `system`。它不是每组各一份，不用于 uTools AI、润色、单组/一级/批量配置测试，也不要求展示完整的默认翻译指令或把模型生成文本当作系统提示词显示。
- **REQ-008｜测试入口**：每组提供独立「测试」按钮，仅对本组真实调用并显示本组成功/安全失败/跳过，不触发组间或一级回退，不改变顺序和历史成功率；原有选中「自定义 AI」的「测试配置」保留，改为测试完整二级组链，成功时指出实际成功组。测试真实消耗服务额度，界面保持可见提示；并发或重复点击不能导致旧结果覆盖当前配置。
- **REQ-009｜一键测试并排序**：继续把自定义 AI 当成五个一级引擎之一；这一项按二级顺序尝试到首个成功或全部未成功，以组链的总耗时及聚合结果参加**一级**测速和排序，二级顺序不自动变化。批量测试与其他四个一级引擎仍可并行；不能再用旧的一级单次时限提前截断自定义组链。测试期间配置/顺序/时限变更或离页时，沿用现有防陈旧覆盖逻辑，批量测试仍不写历史统计。
- **REQ-010｜聚合结算与隐私**：一次普通翻译中的自定义 AI 组链只在一级统计中结算**一次**：至少一组成功为一级 success；未成功且曾有组真实调用失败为一级 failure；所有组都跳过（包括零组）为一级 skipped。组内过程应可在本次反馈/测试结果与脱敏诊断中定位组和分类，但不新增每组长期统计。一级回退提示仍准确显示最终实际一级引擎；提示、日志与测试结果不可泄露 Key、完整 API URL、原文、提示词、响应正文；日志中的组标识只使用安全的稳定 ID/序号及状态，不直接记录用户填写的组名。
- **REQ-011｜运行快照与异常反馈**：一次翻译或一键测试开始时固定本次组顺序、各组参数、共用提示词及二级时限；运行中编辑、排序或删除只影响下一次。仅在当前请求仍有效时展示结果；失败时给安全、可操作的原因或下一一级引擎的回退提示。配置写入失败不得虚报「已保存」。

## 4. 技术方案（后续 Harness 的实施建议）

1. **配置形状与迁移**：建议在 `storage.js` 增加 `thirdpartyAiGroups: [{ id, name, url, apiKey, model }]` 与 `thirdpartyAiFailoverTimeoutSeconds`，保留一份共享的 `thirdpartyAiSystemPrompt`。解析持久化数据时先识别新字段是否**存在**（空数组是合法值），否则才执行单套字段迁移；校验结构、去重 ID/名称并规范化二级时限，避免损坏数据令设置页白屏。新配置写入应沿用现有 dbStorage key，测试老数据、坏数据、零组与重复加载。
2. **二级编排与时限边界**：将组可用性检查、串行尝试、分类与截止计时做成可注入桥接方法的独立逻辑，以配置快照作为输入。复用 `requestThirdpartyAI`、`attemptEngineCall` 等现有模式，每组将剩余/完整的**本组**二级时限传至 preload，渲染侧亦保证截止及晚到结果隔离；524 不等待剩余时限。调整 `runEngineFailover` 对 `thirdparty-ai` 的**一级计时路径**，不能再用一个全局 5 秒 Promise 包住整个组链；其他引擎仍维持现有一级时限。避免每组外再叠加一级时限。若底层请求无法物理取消，至少隔离迟到响应及未处理拒绝。
3. **翻译与结算**：`index.vue` 复用已有方向检测、翻译提示词、`parseResult` 与安全错误分类；组间仅替换 URL/Key/模型，不改变输入方向或解析规则。二级编排返回聚合成败、实际命中的组标识、脱敏的组级结果；调用现有一级成功/失败/跳过回调**一次**，与词典补充、回退标识和日志白名单协调。
4. **设置页与模型/测试**：在当前 `SettingsPage.vue` 以紧凑的组卡片/列表提供编辑、改名、删除确认、排序、单组测试、组内模型拉取，并在组列表外放置二级超时与通用系统提示词。按稳定 ID 管理每组 UI 异步状态；更新后快照/代际检查，拒绝已删除/已变更组的旧响应。浅/深色和小窗口遵守现有 UI 约定。保留其他一级引擎的配置入口与测试。
5. **批量测速适配**：扩展 `engineProbe.js` 的配置快照/不变性比较以覆盖组、组顺序、共用提示词及二级超时；对自定义 AI 使用同一组链编排，以实际组链累计耗时返回一个一级测试项。批量测速自身不走正式翻译统计；其他四引擎并行测试及一级排序原规则不变。组级测试/探测与正式翻译可复用编排，但明确区分是否发送通用提示词及是否写一级统计。
6. **安全与变更范围**：所有联网调用留在已有 preload 桥接，不在 Vue 中新增 `fetch`；网络错误须通过现有脱敏分类路径，日志最少元数据白名单需校验组标识。不要修改无引用的遗留设置组件，不更改 `plugin.json`/路由/端口；对老存储数据保持向后兼容。

## 6. 验收执行方式、操作与标准

**用户将手动验证，Harness 无需执行自动化验证，完成实施并给出手动验证步骤即可。** 下列是供未来实施方交付给用户执行的操作与可观察标准；**本次未执行**。如使用 uTools 开发插件，先按 `TESTING.md` 运行 `pnpm dev`（5175），插件管理 → 开发者 → 添加开发插件 → 选择项目根目录。若需另验安装形态，构建后选 `dist/`；开发版与安装版分开核对。用可控的 OpenAI 兼容测试服务/代理或专用低额度 Key 模拟成功、524、挂起等情况，不在日志中暴露真实凭据。

- **AC-001｜迁移与持久化**：在有旧单套 URL/Key/模型及共享系统提示词的测试用户配置下升级并打开设置：旧数据出现在首组、提示词仍在、一级顺序和一级超时不变；重启后仍仅一个迁移组。新用户默认一个空组；明确删光并重启后仍为零组。
- **AC-002｜组管理**：新增至少两组，分别填不同 URL/Key/模型并命名，修改顺序、重命名后重进仍保持；空名自动生成不重名名称，重名不能保存；删除前需确认，取消不删除，确认后该组及其 Key 消失；零组时该一级引擎跳过并可继续下一一级引擎。
- **AC-003｜组内及一级回退**：将自定义 AI 放到一级首位，组 1 模拟 524/请求失败、组 2 正常、组 3 正常：先调用组 1 再组 2，显示组 2 成功、不调用组 3、不调用下个一级引擎；令两组都失败则继续下个一级引擎并显示正确的实际引擎与安全回退信息。首组成功时不再触发其他组。缺 URL/Key/模型的组不得发请求，依次跳过；全部跳过时一级统计不记 failure。
- **AC-004｜独立逐组超时**：一级设为 1 秒、二级设为 2 秒，前组挂起、后组成功：在约 2 秒（允许调度误差）后开始后组，最终不因一级 1 秒截断自定义组链。反向更改两项，验证二级时限单独生效。二级输入 1、60 均可保存；0、小数、61、空值恢复默认 5；迟到响应不覆盖后组译文或产生重复统计。
- **AC-005｜模型与共用提示词**：不同组分别使用各自的 URL/Key 获取、选择模型，列表/加载/错误不串组；切换、删除或编辑凭据后，旧请求结果不覆盖新值。共用提示词仅有一个入口，修改后对各组的**正式翻译**一致生效；留空则不附加 system 消息；uTools AI、润色和配置测试仍按原有行为。
- **AC-006｜测试入口**：组 1 故障、组 2 成功时点击组 1 的「测试」只显示组 1 的安全失败，不调用组 2/下个一级引擎；原「自定义 AI → 测试配置」则运行完整组链并指出成功组 2。对测试输入/返回检查不写翻译成功率；错误展示不含 Key、完整 URL 或返回正文。测试可能消耗额度的提示可见。
- **AC-007｜一键测试与排序**：配置两组，第一组失败、第二组成功，运行「一键测试并排序」：自定义 AI 仅出现一个一级结果，成功耗时计入组链实际总耗时，仍与其他一级引擎并行测速并按既有一级规则排序；二级组顺序不变，批量测试不写历史成功率，整个组链不会被一级短时限截断。无一级成功时不应改变原有一级顺序。
- **AC-008｜统计与隐私**：对一轮「首组失败、次组成功」普通翻译核对一级自定义 AI 仅记一次 success；所有已调用组失败时仅记一次 failure；全部组跳过仅记 skipped、不进成功率。可定位本轮组级结果/脱敏类别，日志无原文、提示词、组名、Key、完整 URL、响应正文。
- **AC-009｜并发修改及布局**：在翻译或一键测试尚未返回时改 Key、拖拽/删除组、修改二级时限或离开设置页；本轮按启动时快照结算，旧测试不得覆盖新设置/排序或把旧结果误贴到别组。模拟保存失败时不得虚报保存成功；浅色/深色及小窗口里配置、提示、组状态可读且不出现异常滚动。

## 7. 风险与待确认事项

- **累计耗时（已接受的产品取舍）**：二级设置是每组单独的上限、没有组链总上限；多组挂起可能耗时约 `组数 × 二级超时`，随后还可能继续一级回退。必须在 UI 说明真实调用可能耗时及计费。
- **请求物理取消（实现限制）**：渲染层截止和安全忽略迟到结果不等于服务端请求一定被取消；若底层支持中止可传入中止信号，否则保证不会重复结算或污染 UI。
- **迁移与敏感数据**：组配置包含 Key，迁移去重、删除及日志更新需防止旧字段残留或敏感信息泄漏；避免将安全日志中的任意组名视作无害元数据。老版应用不保证识别新组配置（不承诺降级兼容）。
- **现有测试路径的边界差异**：当前单引擎「测试配置」没有翻译超时约束，一键测试有一级单项截止；二级组链必须按本需求分别接入独立时限，并保持其余四个一级引擎行为不变。
- **剩余待确认事项：无阻塞项。** 已确认组顺序及删除、超时粒度与范围、未配置跳过、统计粒度、三类测试、通用提示词范围、迁移与手动验收责任。后续若运行环境暴露本方案无法覆盖的接口限制，再提出具体决策，不将实现猜测冒充已确认需求。
